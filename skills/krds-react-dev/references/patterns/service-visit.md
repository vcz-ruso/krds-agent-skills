# 방문

## 개요

방문은 사용자가 디지털 서비스에 접속하여 원하는 상세 정보로 연결되는 과정으로, 대개 정보 구조의 가장 상위 수준인 서비스의 메인 화면에서 시작된다. 사용자와 서비스가 만나는 첫 지점이므로 서비스에 대한 첫인상을 결정하는 중요한 화면이다. 대부분의 사용자는 구체적인 맥락 없이 서비스를 방문하므로 명확하고 간결하게 구성해야 한다.

메인 화면에서 다루는 콘텐츠 유형은 다음과 같다.

| 유형 | 설명 | 예시 |
| --- | --- | --- |
| 정책 및 서비스 정보 | 정책, 법령, 핵심 운영 서비스 정보 | 정책, 훈령, 예고, 고시 |
| 기관 정보 | 기관/조직이나 장관에 대한 정보 | 공지사항, 알림, 장관 소개 |
| 내비게이션 | 다른 정보·서비스·사이트로 이동하기 위한 링크 그룹 | 자주 찾는 서비스 |
| 캠페인 및 홍보 정보 | 일정 기간 한시적으로 운영되는 시의성 있는 홍보 콘텐츠 | 홍보 배너, 히어로 콘텐츠 |
| 긴급 알림 | 기관/조직 또는 서비스 운영에 대한 긴급 공지사항 | 서비스 중단/서버 점검 알림, 재난 알림 |
| 연락처 | 서비스 운영 담당자 또는 기관의 연락처 | 대표 전화번호, 민원 전화번호, 팩스 번호, 이메일 주소 |

## 사용자 여정 단계

서비스 패턴의 사용성 가이드라인은 사용자 관점의 중요도·만족도에 따라 **[필수]-[권장]-[우수]** 3개 적용 수준으로 구분된다. 핵심 서비스는 최하위 수준인 [필수]를 반드시 준수해야 한다.

### 1. 정보 탐색·확인·이동 (이용 상황별 플로)

방문 과업은 3단계 플로로 진행된다.

1. **정보 탐색** — 정책 및 서비스 정보, 기관 정보, 내비게이션, 캠페인 및 홍보, 긴급 알림, 연락처 등 다양한 유형의 콘텐츠에서 필요한 정보를 찾는 과정.
2. **정보 확인** — 콘텐츠의 의미를 해석하고 인지하는 과정.
3. **이동** — 탐색·확인 과정에서 발견한 정보를 기반으로 서비스 내부 또는 관련 외부 서비스로 이동하는 과정.

메인 화면에 배치되는 콘텐츠 구성 요소 유형: 캐러셀, 탭, 목록과 더보기 링크, 기타 링크 및 버튼.

### 2. 콘텐츠 구성 가이드라인

- **[권장]** 다양한 콘텐츠의 구성 요소를 일관성 있게 구성한다. 메인 화면을 구성하는 요소별 표현·작동 방식을 일관성 있게 구성해 사용자가 정보를 탐색·이동하는 과정에서 불필요한 시간이 소요되지 않도록 해야 한다.
- **[필수]** 시급하거나 중요한 정보를 사용자가 빠르게 인지할 수 있도록 제공한다. 서비스 점검이나 기능 중단 등 이용 전 반드시 알아야 하는 정보는 가장 먼저 인지할 수 있도록 구성해야 한다.
- **[권장]** 사용자 데이터를 기반으로 한 우선순위에 따라 콘텐츠를 배치한다. 제공자 관점으로만 우선순위를 결정하면 사용자가 주로 찾는 정보가 찾기 어려운 곳에 배치되어 방문 단계부터 목적을 달성할 수 없게 된다.
- **[권장]** 사용자 관점에서 같은 목적의 콘텐츠들은 섹션으로 모아서 구성한다. 산발적으로 배치하거나 목적이 다른 콘텐츠를 한 섹션에 모으면 직관적인 탐색이 어렵다. 섹션에는 명확한 타이틀과 간단한 안내를 제공해야 한다.
- **[권장]** 방문 목적 및 사용자 유형별로 핵심 정보와 서비스를 탐색할 수 있는 영역을 구성한다. '방문 목적별/사용자 유형별 바로가기', '자주 찾는 서비스' 방식으로 사용자가 원하는 정보를 직접 선택·탐색·이동할 수 있는 기능을 제공해야 한다.
- **[우수]** 로그인 기반의 개인화된 바로가기 영역을 배치한다. 방문 빈도가 높고 반복적인 과업을 수행하는 사용자에게는 로그인 기반 행동 패턴 분석을 활용한 개인화 서비스가 효과적이다. 로그인 기능이 없다면 이용 빈도가 높은 바로가기 영역을 배치해 탐색 시간을 단축한다.
- **[권장]** 사용자가 정보를 빠르게 구분하고 정확하게 이동할 수 있는 방법을 제시한다 — 최신 업데이트·기한 표시 레이블 제공, 용어 및 콘텐츠의 간략한 설명, 외부 사이트로 이동하는 링크의 표시.
- **[필수]** 최신의 정확한 정보를 제공한다. 메인 화면 콘텐츠가 최신이 아니거나 부정확하면 사용자는 서비스가 정상적으로 운영·관리되고 있지 않다고 판단할 수 있다. 최신성·정확성을 수시로 점검해야 한다.
- **[권장]** 콘텐츠 및 서비스 명칭은 친숙하고 일관성이 있어야 한다. 서비스 내 다른 영역에서 동일 용어가 다르게 제공되면 사용자가 이동 과정에서 혼동을 겪을 수 있다.

## 관련 KRDS 컴포넌트

| 컴포넌트 | 비고 |
| --- | --- |
| Tab | 메인 화면 콘텐츠 구성 요소(주제별 탐색 등)로 사용 |
| Link | "목록과 더보기 링크", "기타 링크 및 버튼" 구성 요소 |
| Button | "기타 링크 및 버튼" 구성 요소 |

원문은 메인 화면 구성 요소로 "캐러셀"도 명시하지만, 캐러셀은 KRDS 표준 컴포넌트 목록에는 있고 스타일 가이드(`data/site/style/style_07.md`)에서도 "외부 플러그인을 사용한 컴포넌트"로 별도 취급되는 항목으로, krds-react 39종 컴포넌트에는 구현되어 있지 않다(`references/components/README.md` 기준). 캐러셀형 콘텐츠가 필요하면 별도 라이브러리 조합을 검토해야 한다.
