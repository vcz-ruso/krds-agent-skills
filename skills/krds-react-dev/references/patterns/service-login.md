# 로그인

## 개요

로그인은 사용자의 신원을 확인하는 과정으로, 사용자가 서비스에 접근할 수 있도록 하는 수단이다. 사용자에게 개인화된 경험을 제공하거나 사용자의 신분/신원을 인증하고자 하는 경우에 사용하기 적합하다.

**유형**

| 인증 유형 | 설명 | 예 |
| --- | --- | --- |
| 지식 기반 인증 | 사용자만이 유일하게 알고 있는 내용에 기반 | 아이디/패스워드, PIN |
| 소유 기반 인증 | 사용자가 보유한 품목을 활용 | 토큰, 공동인증, 간편인증, 문자 인증 |
| 생체 기반 인증 | 사용자의 생체 정보·행동에 기반 | 지문 인증, 페이스 아이디 |
| 다중 요소 인증 | 여러 인증 방식을 결합 | — |

이용 상황별 플로: (1) 로그인 방식 확인·선택 → (2) 로그인 정보 입력 → (3) 로그인 완료 → (4) 로그아웃(자발적 또는 세션 만료로 자동 발생).

서비스 패턴의 사용성 가이드라인은 사용자 관점의 중요도·만족도에 따라 **[필수]-[권장]-[우수]** 3개 적용 수준으로 구분된다. 핵심 서비스는 최하위 수준인 [필수]를 반드시 준수해야 한다.

## 사용자 여정 단계

### 1. 로그인 기능 찾기

**구조**: ① 아이콘(로그인 링크임을 직관적으로 인지시키는 아이콘), ② 레이블(아이콘의 텍스트 레이블).

- **[필수]** 로그인 링크는 모든 화면에서 일관된 위치에 주목도 있게 배치한다. 일부 화면에만 제공되면 로그인이 필요한 사용자가 이용에 어려움을 겪는다.
- **[권장]** 헤더에서 제공되는 로그인 링크는 사용자 아이콘과 레이블로 구성한다. 아이콘 단독 사용은 목적을 빠르게 이해하기 어렵다.
- **[필수]** 로그인 링크는 항상 '로그인' 화면(또는 계정 선택 화면)으로 연결되어야 한다.

**플랫폼 고려 사항**: 화면 너비가 충분하지 않아도 로그인 링크를 직관적으로 인지할 수 있는 형태로 표현한다 — 헤더나 탭바 영역에 로그인/마이페이지 링크를 상시 배치(로그인이 중요하지 않은 서비스라면 메뉴 레이어에서만 제공 가능). 서비스 중심 모바일 앱에서는 탭바 하단에 로그인 버튼을 상시 노출한다.

**접근성 가이드라인**: 로그인 링크는 스크린 리더에서 링크로 인지될 수 있어야 한다 — 버튼 요소로 마크업하면 화면 이동 동작을 예측할 수 없다. 관련: WCAG 2.1 Name, Role, Value(A).

### 2. 로그인 안내

**구조**: ① 오버레이, ② 헤더(모달 제목), ③ 닫기 버튼(선택), ④ 본문, ⑤ 푸터('로그인 안 함' 옵션, 로그인 이동 링크 등 액션 버튼).

**유형**: 기본(로그인 필수 화면/기능 접근 시), 추천(로그인 방식에 따라 이후 절차가 달라질 때), 제안(필수는 아니지만 이점이 있어 제안).

- **[권장]** 로그인에 대한 안내는 모달로 제공하여 사용자의 과업 맥락이 유지될 수 있도록 한다.
- **[권장]** 로그인은 꼭 필요한 상황에서 유도한다 — 기본/추천 유형은 로그인 필수 기능의 액션 버튼 실행 시점에, 제안 유형은 화면 로딩 후 제공한다.
- **[우수]** 로그인을 제안하는 경우 모달 본문에서 로그인을 통해 얻을 수 있는 이점(및 하지 않았을 때의 어려움)에 대해 명확한 설명을 제공해야 한다.
- **[우수]** 사용자가 이용 절차를 단축할 수 있는 로그인 방식을 추천한다(예: 특정 방식이 본인 인증 과정을 건너뛸 수 있다면 그 방식을 추천).
- **[권장]** 로그인 안내 모달에는 '로그인 안 함' 옵션을 제공하여 원하지 않는 이동 동작이 발생하지 않도록 한다.

관련 기본 패턴: 확인.

### 3. 로그인 방식 확인/선택

**구조**: ① 부제목, ② 제목, ③ 설명, ④ 방식 선택 목록, ⑤ 방식 선택 탭(통합 로그인/기존 서비스 로그인 분리), ⑥ 섹션 제목, ⑦ 방식 선택 목록(서비스 범위별), ⑧ 디스클로저(세부 정보 표시/숨김), ⑨ 로그인 관련 도움말 링크, ⑩ 회원 가입 링크.

**유형**

| 구분 | 종류 | 설명 |
| --- | --- | --- |
| 레이아웃 | 목록 / 탭 | 인증 방식 15개 이하면 목록, 15개 초과면 탭 |
| 절차 | 단일형 | 한 화면에서 로그인 방식 비교·선택 |
| 절차 | 단계형 | 여러 레이아웃을 거쳐 선택지를 좁힘(인증 주체·권한 수준이 다르거나 이용 빈도가 낮을 때) |
| 절차 | 집중형 | 단계형에서 마지막 로그인 방식을 저장해 다음부터 단계 생략(이용 빈도가 높을 때) |

- **[우수]** 빈번하게 사용되는 로그인 방식에 우선적으로 접근할 수 있는 수단을 제공한다.
- **[권장]** 동일한 수준의 로그인 방식을 탭으로 구분하여 선택하게 하지 않는다 — 탭은 두 콘텐츠를 동시에 비교하기 적합한 레이아웃이 아니다. 로그인 주체·방식이 명확히 구분될 때만 탭을 사용한다.
- **[권장]** 다양한 로그인 방식에 대한 분류 체계에 사용자의 관점과 언어를 반영한다(기술적 관점이 아닌 이용 목적 기준).
- **[권장]** 로그인 방식에 따라 서비스 이용 절차가 달라지는 경우, 사전에 안내를 제공한다.
- **[권장]** 로그인 방식과 입력 항목에 대한 직관적인 안내를 해당 항목 주변에 제공한다.
- **[권장]** 도움말 정보, 매뉴얼 링크를 제공한다.
- **[필수]** 도움말 정보는 사용자의 다양한 이용 환경(디바이스, 화면 크기)을 고려하여 작성한다.

**접근성 가이드라인**: 인지 기능 테스트에 의존하지 않는 인증 방식을 적어도 하나 이상 제공해야 한다(비밀번호 입력, 패턴 인식, 임의 문자열 기억, 계산, 이미지 찾기 등에만 의존 금지 — 단, 사용자에게 익숙한 이름·이메일·전화번호는 인지 기능 테스트로 간주하지 않음). 관련: KWCAG 2.2 접근 가능한 인증.

**플랫폼 고려 사항**: 작은 화면에서는 로그인 방식 전체를 한눈에 확인할 수 있도록 우선 배치한다.

관련 기본 패턴: 도움, 입력폼.

### 4. 로그인 정보 입력

**구조**: ① 레이블, ② 계정 정보 입력 필드, ③ 로그인 정보 저장 옵션(체크박스), ④ 아이디/비밀번호 찾기 링크, ⑤ 도움말.

- **[필수]** 아이디 형식에 대한 단서를 사전에 제공한다 — 플레이스홀더가 아닌 레이블·도움말로 제공(예: 이메일 형식 아이디).
- **[필수]** 비밀번호를 표시할 수 있는 옵션('비밀번호 표시' 버튼)을 제공한다.
- **[필수]** 복사/붙여넣기를 제한하지 않는다.
- **[우수]** 로그인 정보를 저장할 수 있는 옵션을 제공한다(저장 항목·기간 안내 병행 가능).
- **[필수]** 아이디/비밀번호 찾기 링크를 제공한다.
- **[필수]** 오류 메시지는 명확하고 간결하게, 구체적으로 제공한다.

**접근성 가이드라인**: 초점이 논리적인 순서로 이동해야 한다(비밀번호 입력 전에 로그인 버튼으로, 로그인 버튼 이후 저장 옵션으로 초점이 튀지 않아야 함 — KWCAG 2.2 초점 이동과 표시/콘텐츠의 선형 구조, WCAG 2.1 Focus Order(A)/Meaningful Sequence(A)). 입력 필드에 `autocomplete` 속성을 설정해 자동완성 정보를 사용자 에이전트에 전달한다(WCAG 2.1 Identify Input Purpose(AA)).

**상호작용 가이드라인**: 제출 전 가능한 한 많은 사용자 데이터의 유효성을 검사한다(포커스 아웃 시 실시간 검증). 제출 후 오류 발생 시 해당 항목으로 초점을 이동시킨다 — 서버 측 오류는 화면을 다시 로드하고 비밀번호 필드를 비운 뒤 아이디 입력 필드로 사용자를 되돌리고, 인라인 메시지로 해결 방법을 안내한다.

**플랫폼 고려 사항**: 생체인식을 사용할 경우 자동로그인 기능을 추가한다(기본값은 기관 보안정책에 따름).

관련 기본 패턴: 입력폼, 오류.

### 5. 로그인 완료

**구조**: ① 사용자 이름(프로필 사진 포함 가능, 개인화 메뉴 실행 트리거), ② 로그아웃 버튼, ③ 개인화 메뉴(드롭다운/드로어), ④ 로그아웃까지 남은 시간, ⑤ 로그인 연장 버튼.

- **[권장]** 로그인이 완료된 후, 로그인 상황에 적합한 화면으로 이동해야 한다 — 의도적 로그인이면 탐색 중이던 화면으로, '로그인 안내' 단계를 거쳤다면 접근/탐색을 시도하던 화면으로.
- **[권장]** 로그인 상태로 전환되었음을 명확하게 표현한다 — 로그인 기능을 로그아웃 옵션으로 전환하는 등의 방법으로. 마이페이지 레이어에 사용자 이름을 표시하면 개인정보 보호와 상태 표현을 동시에 만족한다.

**접근성 가이드라인**: 로그인 완료 후 화면 로딩 시 초점은 문서 가장 처음부터 접근되어야 한다(헤더·본문으로 임의 이동 금지). 관련: KWCAG 2.2 초점 이동과 표시, WCAG 2.1 Focus Order(A).

### 6. 서비스 이용 (세션 유지·만료 안내)

**구조**: ① 오버레이, ② 헤더(만료 임박 안내), ③ 닫기 버튼(선택), ④ 본문, ⑤ 로그아웃까지 남은 시간, ⑥ 푸터(연장/로그아웃 액션), ⑦ 로그인 연장 버튼.

**유형**: 로그인 만료 안내 모달(전역 제공), 로그인 세션 유지 시간 안내(작업 손실 위험이 있는 화면에서 사전 안내).

- **[필수]** 사용자에게 로그인 세션이 만료되기 전에 유지 시간에 제한이 있음을 안내한다.
- **[권장]** 로그인 세션 시간 만료에 대한 안내는 모달로 제공하여 과업 맥락이 유지되도록 한다.
- **[필수]** 로그인 세션 시간 만료에 대한 안내는 세션이 만료되기 최소 20초 전에 제공한다(시스템 반응이 느리면 더 긴 시간 권장).
- **[필수]** 로그인 만료 안내 모달에 시간 연장하기 버튼과 로그아웃하기 버튼을 제공한다.

**접근성 가이드라인**: 만료 안내 모달이 활성화된 상태에서 아무 키나 눌러도 연장되도록 고려한다(KWCAG 2.2 응답시간 조절, WCAG 2.1 Timing Adjustable(A)). 시간 연장은 최소 10회 이상 수행할 수 있도록 제공한다(동일 근거 규정).

### 7. 로그아웃

**구조**: ① 제목, ② 본문(전환 이유 설명), ③ 액션 버튼(메인 이동 링크, 다시 로그인하기 버튼).

**유형**: 사용자 요청에 의한 로그아웃, 이용 세션 만료에 의한 로그아웃.

- **[권장]** 로그아웃 상태로 전환되었음을 분명하게 보여준다(로그인 실행 버튼 레이블을 '로그인'으로 전환하는 등).
- **[우수]** 사용자 요청에 의해 로그아웃이 실행되는 경우 결과 화면과 로그아웃 실행 사이에 스피너를 제공한다.
- **[권장]** 로그아웃이 완료된 후, 상황에 적합한 화면으로 이동해야 한다 — 의도적 로그아웃은 메인 화면으로, 세션 만료는 로그아웃 완료 화면으로.
- **[우수]** 로그아웃에 대한 안내는 별도의 화면으로 구성하여 제공한다.
- **[우수]** 로그아웃 안내 화면에 사용자의 행동을 유도할 수 있는 액션 버튼('다시 로그인하기' 등)을 제공한다.
