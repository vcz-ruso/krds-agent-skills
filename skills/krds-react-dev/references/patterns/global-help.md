# 도움

## 개요

도움 패턴은 사용자에게 서비스를 이용하는 동안 사용자 인터페이스의 작동 방식과 사용 방법, 진행 중인 과업 플로(Flow) 등과 관련된 도움 정보를 제공하는 데 사용되는 다양한 유형의 컴포넌트 조합이다. 사용자의 능숙도와 이용 맥락에 적합한 도움 컴포넌트를 설계하여 제공함으로써 사용자는 보다 쉽고 빠르게 서비스를 이해하고 이용할 수 있게 된다.

## 유형

| 유형 | 설명 | 적합한 상황 | 하위 요소/컴포넌트 |
| --- | --- | --- | --- |
| 고정형 도움말 | 사용자가 요청하지 않아도 UI·콘텐츠 주변에 항상 표시. 모든 사용자가 반드시 확인해야 하는 정보를 전달 | 이용 빈도가 높은 사용자, 익숙한 기능/화면 | 섹션 헤딩 및 설명, 레이블, 인라인 텍스트, 플레이스홀더 |
| 사용자 요청에 의한 도움말 | 사용자의 현재 작업과 관련된 상황적·시기적절한 도움말. 도움말 표시 버튼 클릭 시 화면 이동 없이 요소 주변에 제공 | 신규/초보 사용자, 복잡한 서비스, 새로운 기능/정보를 도입한 화면 | 툴팁, 맥락적 도움말, 도움 패널, 코치마크, 따라하기 패널 |
| 반응형 도움말 | 사용자의 맥락을 벗어난 별도 화면에서 제공되는 정보·문서 리소스 | 사용자가 문제를 겪는 상황에서 스스로 탐색 | 예: 자주 묻는 질문, 도움말 메뉴 |

## 사용성 가이드라인

### 공통

- **과업의 난이도와 복잡성을 고려하여 사용자에게 적절한 도움을 제공한다.** 복잡도가 낮거나 대부분의 사용자에게 익숙한 화면에는 고정형 도움말을, 복잡도가 높거나 새로운 기능/화면에는 사용자 요청에 의한 도움말을 사용하는 것이 좋다.
- **도움말 콘텐츠는 명확하고 간결한 내용으로 작성한다.** 도움 패턴은 오류·문제 상황을 예방하는 데 중요하지만 동시에 사용자의 작업 집중을 방해할 수 있으므로, 관련성 높고 유용한 정보를 사용자 관점에서 적시에 제공해야 한다.
- **도움말 콘텐츠는 포괄적이고 유연한 내용으로 작성한다.** 특정 이용 환경·조건에서만 참고할 수 있는 내용으로 제공하지 않아야 한다.
- **사용자 요청에 의한 도움말 콘텐츠는 반응형 방식으로도 사용할 수 있도록 한다.** 복잡한 기능/화면에서는 도움이 필요한 맥락이 아니어도 콘텐츠를 다시 확인하고 싶을 수 있다.
- **동일한 페이지 제목, 버튼 이름을 지칭하기 위한 텍스트는 모든 서비스에서 동일하게 사용한다.** 동일한 목적지/기능에는 일관성 있는 텍스트 표현을 사용해야 학습 없이 효율적으로 콘텐츠를 탐색할 수 있다.
- **관련 화면/리소스 링크는 새 탭에서 화면이 연결되도록 제공한다.** 현재 탐색 중인 화면·과업의 맥락을 잃지 않도록 한다.

### 안내 영역

- **안내 영역은 본문을 이해하고 이용하는 데 포괄적으로 이해가 필요한 정보를 전달하는 데 사용한다.** 포함할 수 있는 정보 예: 취소/수정 가능 여부, 전자서명/본인인증 절차 포함 여부, 제출할 증빙서류, 기타 안내 사항.
- **안내 영역은 본문 상단에 배치한다.** 하단에 배치하면 정보가 필요한 순간에 접근할 수 없다.
- **한 화면에 여러 개의 안내 영역을 사용하지 않는다.** 여러 개면 사용자가 중요한 정보에 집중하기 어렵다. 중요한 정보만 간결하게 담고, 필요하면 디스클로저 컴포넌트를 활용하되(접힌 상태로 표시) 반드시 확인해야 할 중요한 정보는 디스클로저 안에 담지 않는다.

### 플레이스홀더

- **플레이스홀더를 레이블이나 도움말의 대체 수단으로 사용하지 않는다.** 값을 입력하기 시작하면 사라지므로 인라인 텍스트와 동일하거나 추가 정보가 없어서는 안 된다. 값 입력 힌트/예시(날짜·숫자 입력 형식 안내, 입력 가능 자릿수 표시) 목적에는 사용할 수 있으나, 이 경우에도 동일한 텍스트를 인라인 텍스트로 함께 제공해야 한다.

### 인라인 텍스트

- **사용자가 작업을 완료하는 데 필요한 중요한 정보는 인라인 텍스트로 제공한다.** 사용자 요청에 의한 도움말은 발견이 어려울 수 있으므로, 반드시 확인해야 하는 정보는 요소에 인접한 인라인 텍스트로 제공하는 것이 적합하다.

### 툴팁

- **컨트롤 요소에 대한 레이블과 같이 간단한 추가 정보를 제공하는 데 툴팁을 사용한다.** 도움 정보가 1~2단어 또는 한 문장으로 간결한 경우(예: 아이콘 단독 컨트롤에 레이블 표시)에 사용한다.

### 맥락적 도움말

- **컴포넌트의 상태나 관련된 상세 정보를 제공하는 데 맥락적 도움말을 사용한다.** 컴포넌트나 레이블 옆에 배치해 부가 정보, 유용한 정보, 과업을 적극적으로 돕는 정보를 제공한다.

### 도움 패널

- **도움말 콘텐츠의 양이 많거나 복잡한 과업에 도움 패널을 사용한다.** 개별 화면 수준의 도움말이 필요할 때 사용하며, 주로 제공되는 정보 예: 과업 수행의 결과, 입력 필드의 구성과 입력이 필요한 이유, 선택적 입력 사항 결정에 참고할 정보, 입력 필드 값 입력 방법, 서비스 정의·복잡한 용어 설명.

### 코치마크와 따라하기 패널

- **작업을 완료하는 방법에 대한 단계별 안내가 필요한 복잡한 과업에 코치마크와 따라하기 패널을 사용한다.** 이용 빈도가 매우 낮고 여러 단계의 입력으로 구성된 과업에 적합하다.

## 관련 KRDS 컴포넌트

| 컴포넌트 | 대응 유형 |
| --- | --- |
| Tooltip | 툴팁 |
| ContextualHelp | 맥락적 도움말 |
| HelpPanel | 도움 패널 |
| CoachMark | 코치마크 |
| TutorialPanel | 따라하기 패널 |
| Disclosure | 안내 영역 내 부가 정보(디스클로저) |

TextInput 등 입력 컴포넌트의 레이블·플레이스홀더 속성은 "고정형 도움말" 유형(레이블, 인라인 텍스트, 플레이스홀더)에 대응하지만, 원문은 이를 별도 컴포넌트가 아니라 입력 컴포넌트의 속성으로 다룬다.
