# 검색

## 개요

검색은 사용자가 큰 데이터 집합에서 원하는 정보를 찾도록 돕는 기능이다. 무엇을 찾을지 아는 경우 일차적인 정보 탐색 수단으로, 탐색으로 원하는 콘텐츠를 찾지 못하는 상황에서는 특정 정보와 관련된 단서를 제공해 필요한 콘텐츠를 쉽게 찾도록 돕는다.

**사용하기 적합하지 않은 경우**: 단일 화면 웹사이트나 규모가 매우 작은 서비스에서는 통합 검색 없이 정보를 탐색할 수 있다.

**유형**

| 유형 | 설명 | 예 |
| --- | --- | --- |
| 통합검색 | 웹사이트/애플리케이션 전체 검색. 서비스에 익숙하지 않은 사용자가 데이터 구조와 정보를 파악하는 데 쓰인다. 보통 헤더에 배치, 결과는 별도 화면에서 제공 | 웹사이트 통합 검색, 자료 검색 |
| 부분 검색 | 소규모 웹사이트, 단일 화면 서비스, 특정 정보 목록·표 등 소규모 데이터 집합 검색. 데이터 집합 상단에 배치, 결과가 데이터 집합에 직접 반영 | 게시물 검색, 목록 부분 검색 |

이용 상황별 플로: (1) 검색어 입력 → (2) 검색 결과 확인 → (3) 검색 결과 이용 → (4) 재검색 / (5) 상세 검색.

서비스 패턴의 사용성 가이드라인은 사용자 관점의 중요도·만족도에 따라 **[필수]-[권장]-[우수]** 3개 적용 수준으로 구분된다. 핵심 서비스는 최하위 수준인 [필수]를 반드시 준수해야 한다.

## 사용자 여정 단계

### 1. 검색 기능 찾기

**구조**: ① 돋보기 아이콘(검색 실행/검색 레이어·화면 실행 버튼), ② 레이블(돋보기 아이콘의 텍스트 레이블, 버튼으로 함께 작동).

- **[필수]** 서비스 내 모든 화면에서 통합 검색 기능을 실행할 수 있도록 한다. 일부 화면에서만 제공되면 사용자가 검색 기능이 없다고 오인해 정보를 발견하지 못할 수 있다.
- **[권장]** 통합 검색 기능 실행 버튼은 모든 화면에서 헤더 우측에 일관성 있게 배치한다. 화면 오른쪽 상단은 사용자가 기대하는 위치다.
- **[권장]** 통합 검색 기능은 검색어 입력 필드+돋보기 버튼 조합, 또는 돋보기 버튼 단독 형태로 사용한다. 메인 메뉴 링크가 적거나 텍스트가 간결하면 입력 필드 노출형이, 링크가 많거나 도움말을 풍부히 제공하려면 버튼 단독형(실행 시 별도 레이어/페이지로 검색어 입력)이 적합하다. 후자는 '검색'/'통합검색' 텍스트 레이블을 반드시 함께 사용해야 한다.
- **[권장]** 부분 검색 기능은 콘텐츠 목록의 수준·맥락을 고려해 사용자가 예측할 수 있는 영역(기본: 목록 레이아웃 우측 상단, 복잡한 검색은 목록 상단 전체)에 배치한다.
- **[권장]** 검색 기능 주변에 불필요한 요소의 배치를 최소화한다. 다른 기능 버튼·안내 배너 등이 주변에 있으면 검색 인터페이스의 현출성이 저하된다.

**접근성 가이드라인**

- 돋보기 아이콘은 키보드 및 스크린 리더로 접근·조작할 수 있어야 한다(별도 검색 페이지로 이동하지 않는 한 모든 플랫폼에서 버튼 역할로 구현). 관련: KWCAG 2.2 키보드 사용 보장, WCAG 2.1 Keyboard(A)/No Keyboard Trap(A)/Name, Role, Value(A).
- 돋보기 아이콘에 적절한 이름을 제공한다 — 레이블이 없는 버튼의 접근 가능한 이름은 '돋보기'가 아니라 '검색' 또는 '통합 검색'으로 제공해야 한다. 관련: KWCAG 2.2 적절한 링크 텍스트, WCAG 2.1 Headings and Labels(AA).

### 2. 검색어 입력

**구조**: ① 검색어 입력 필드, ② 레이블, ③ 돋보기 아이콘(검색 실행 버튼), ④ 플레이스홀더(선택), ⑤ 검색어 삭제 버튼, ⑥ 스코프 필터(선택), ⑦ 실시간 검색어 제안(선택), ⑧ 검색 도움말(선택).

- **[우수]** 사용자가 검색어 입력 행위에 집중할 수 있도록 한다. 헤더 확장형 검색 필드 사용 시, 필드와 실시간 제안 레이어 외 영역의 명도·불투명도를 낮춘다.
- **[필수]** 스코프 필터를 사용하는 경우 '전체' 옵션을 제공한다. 스코프 필터는 한 번에 하나만 선택 가능하므로 항상 '전체'를 기본값으로 제공해야 한다.
- **[권장]** 검색어 입력 필드는 일반적인 검색어가 한눈에 파악될 수 있는 너비로 제공하고 줄바꿈·말줄임표를 사용하지 않는다.
- **[필수]** 통합 검색이 아닌 검색에는 입력 필드에 레이블을 제공한다. 통합 검색은 용도가 명확해 레이블이 없어도 되지만, 범위 검색·길찾기 등 부분 검색은 대상에 대한 단서를 간결·명확하게 제공해야 한다.
- **[필수]** 플레이스홀더를 사용하는 경우, 유도 문구 외에 검색에 대한 단서나 레이블을 포함해서는 안 된다. 플레이스홀더는 입력 시작과 동시에 사라져 도움이 되지 않는다.
- **[권장]** 사용자에게 다양한 방식의 검색어 입력 도움을 제공한다 — 검색어 예제, 많이 사용된 검색어, 이전 입력 검색어, 첫 단어 제안, 검색 도움말 등.
- **[우수]** 검색어 입력 도움은 가능한 사용자가 입력하는 시점에 실시간으로 제공한다. 입력 시간을 단축시켜 빠른 검색을 돕는다.
- **[권장]** 실시간으로 검색어를 제안할 수 없는 경우, 검색 결과 화면에서 보조적인 도움 수단을 제공한다.

**플랫폼 고려 사항**: 음성입력 버튼을 제공한다 — 키보드 입력이 어려운 상황, 특히 디지털취약계층을 위해 음성 검색어 입력을 지원한다. 재검색 관련 고려사항으로, 검색 컨트롤이 많아 화면이 복잡한 경우 필수 조건을 제외한 상세 검색 컨트롤은 모달/바텀시트 등으로 숨김 처리할 수 있다.

**접근성 가이드라인**

- 검색어 입력/실행 컨트롤에 적절한 이름을 제공한다 — 검색어 입력 필드/검색어 전체 삭제/검색 버튼에 각각 '검색어', '검색어 전체 삭제', '검색'이라는 접근 가능한 이름을 제공. 관련: KWCAG 2.2 적절한 링크 텍스트·레이블 제공, WCAG 2.1 Headings and Labels(AA)/Name, Role, Value(A).
- 검색어 입력/실행 관련 대화형 요소는 키보드로 접근·조작 가능해야 한다. 관련: KWCAG 2.2 키보드 사용 보장, WCAG 2.1 Keyboard(A)/No Keyboard Trap(A).
- 자동완성·추천 검색 정보에 보조 기술이 접근할 수 있도록 제공한다.
- 실시간 검색어 입력 도움창의 출현 및 추천 검색어를 스크린 리더가 탐지할 수 있도록 WAI-ARIA를 활용한다. 관련: WCAG 2.1 Status Messages(AA).
- 실시간 검색어 입력 도움창은 검색어 입력 필드의 다음 요소로(필드와 검색 버튼 사이에) 제공한다. 관련: KWCAG 2.2 콘텐츠의 선형화, WCAG 2.1 Meaningful Sequence(A).
- 자동완성·추천 검색어 목록을 계층화해 제공한다. 관련: KWCAG 2.2 제목 제공, WCAG 2.1 Info and Relationships.

**상호작용 가이드라인 — 검색어 입력 필드**

| 이벤트 | 동작 |
| --- | --- |
| Focusin | 값이 없는 상태로 포커스를 받으면 인기 검색어·이전 검색 기록 제공 |
| Keyup | 한 글자 이상 입력 시 인기 검색어·이전 기록이 검색어 제안으로 전환, 돋보기 버튼 왼쪽에 검색어 삭제 버튼 노출 |
| Enter | 검색 실행 |
| 방향키 ↓ | 검색어 제안 목록의 첫 번째 요소로 초점 이동 |

**상호작용 가이드라인 — 실시간 검색어 입력 도움**

| 이벤트 | 동작 |
| --- | --- |
| 방향키 ↑/↓ | 제안 목록 순회(첫/마지막 항목에서 반대 방향키로 순환) |
| Click | 선택 항목으로 검색 실행 |
| Enter | 초점 항목으로 검색 실행 |
| Esc | 도움창 닫힘, 초점이 검색어 입력 필드로 복귀 |

### 3. 검색 결과 확인

**구조**: ① 주제 탐색 탭(별도 필터/고급 검색 없이 결과를 주제별로 탐색), ② 결과 수, ③ 결과 목록.

- **[우수]** 검색 결과가 표시되기 전에 로딩 상태 정보를 제공한다 — 스피너·스켈레톤, 느린 경우 진행률 표시 막대.
- **[필수]** 검색 결과 화면에 검색어 입력 필드를 유지한다(연속 검색 가능하도록).
- **[권장]** 검색 결과 화면에 여러 개의 검색어 입력 필드를 사용하지 않는다.
- **[권장]** 사용자가 재검색을 시도하지 않는 한 검색어 입력 필드에 검색어를 유지한다.
- **[필수]** 검색 결과 수를 표시한다(주제별 탭 구분 시 주제별 결과 수도 필수).
- **[필수]** 검색어와 관련된 결과가 반환되는지 확인한다(정기 점검).
- **[우수]** 유사 검색어·관련 검색어에 대한 결과를 함께 제공한다.
- **[권장]** 초기 검색 결과 목록은 정확도 또는 관련도순으로 정렬해 제공한다.
- **[우수]** 검색 결과가 지나치게 많은 경우 범위를 제한할 수 있는 방법을 안내한다(예: "원하는 결과를 찾지 못하셨나요? 고급 검색을 사용해 보세요.").
- **[필수]** 검색 결과가 없는 경우, 결과를 명확하게 알리고 적절한 대안을 제공한다 — 결과 수 "0" 표시, "검색어와 일치하는 결과를 찾을 수 없습니다." 안내, 검색어 철자 확인/다른 검색어 사용/더 일반적인 검색어 사용/검색 도움말 참조 등 대안 행동 제시.

### 4. 상세 검색

**구조**: ① 정렬 컨트롤, ② 필터 컨트롤, ③ 고급 검색 버튼/링크(정렬·필터로 처리 못하는 복잡한 조건 설정).

**유형**

| 유형 | 특징 |
| --- | --- |
| 기본 검색 | 기본 정렬·필터 컨트롤만 사용, 목록 상단에 막대 형태로 모든 컨트롤을 시각적으로 노출 |
| 복합 검색 | 더 많은 유형·속성의 필터, 목록 상단 막대 또는 사이드 패널에 배치 |
| 고급 검색 | 여러 키워드 조합/다중 조건, 세부 조건을 모달이나 별도 화면에서 설정 — 조건 설정에 집중이 필요하거나 부가 설명이 필요하거나 조회 시간이 긴 경우 적합 |

- **[필수]** 기본 정렬, 필터 컨트롤을 제공한다 — 통합검색은 검색 기간 필터·기본 정렬 필수. 검색 기간 필터는 사용자 정의 + 3개 이상 사전 정의 옵션(예: 오늘/일주일/1개월), 기본 정렬은 정확도/관련도순·최신순·인기순.
- **[권장]** 기본 검색에서 정렬, 필터 컨트롤은 일정한 순서(검색 기간 필터 → 기본 정렬)로 제공하고 군집화한다.
- **[필수]** 스코프 필터를 사용하는 경우 결과 페이지 상단에 설정된 범위를 명시적으로 표시한다.
- **[우수]** 정렬, 필터 적용 결과는 가능한 한 사용자가 값을 선택하였을 때 적용한다(데이터가 많지 않고 성능 문제가 없는 경우).
- **[우수]** 조건이 적용되었음을 확인할 수 있는 명확한 시각적 단서를 제공한다.

**접근성 가이드라인**: 조건이 적용되었음을 확인할 수 있는 명확한 프로그램적 단서를 제공한다 — 전체 검색 결과 수 안내 텍스트에 live-region을 적용하고 `aria-live="polite"`로 변경 즉시 스크린 리더에 전달되도록 한다. 관련: WCAG 2.1 Status Messages(AA).

### 5. 검색 결과 이용

**구조**: ① 주제 탐색 탭, ② 배지(선택, 범주 관련 메타데이터), ③ 날짜, ④ 제목, ⑤ 설명, ⑥ 인덱스(정보 구조 위계), ⑦ URL(선택, 외부 사이트 연결 시), ⑧ 액션 버튼 또는 링크(선택).

- **[필수]** 사용자가 필요로 하는 주제별로 검색 결과가 제공되도록 설계한다 — 메뉴, 자주 묻는 질문, 뉴스/공지/소식, 첨부파일 등 자료, 정책/고시/법령, 이미지/동영상 등 미디어, 직원.
- **[권장]** 검색 주제 분류는 7개를 초과하지 않도록 한다.
- **[권장]** 주제별 탐색 탭을 사용하는 경우 전체 목록이 가장 첫 번째 탭으로 제공되어야 한다.
- **[우수]** 전체 결과 목록은 주제별 섹션 구분 없이 결과의 정확도·관련도 순으로 정렬한다(이미지·동영상처럼 비텍스트 주제이거나 근거가 명확한 경우에만 섹션 구분).
- **[권장]** 제목과 설명은 명확하고 간결하게(2줄 이내, 초과 시 말줄임표) 제공한다.
- **[권장]** 항목에 검색 결과 범주 정보가 명확하게 드러나도록 표현한다.
- **[필수]** 검색어와 일치하는 항목을 강조 표시한다.
- **[권장]** 기본 검색 결과 목록에 표시되는 항목의 수를 10개 이상으로 제공한다(항목이 간결하거나 데이터 규모가 크면 표시 수 조정 옵션 제공 권장).

### 6. 재검색

**구조**: ① 정렬 컨트롤, ② 필터 컨트롤.

- **[필수]** 상세 검색 컨트롤을 숨기지 않는다(화면 너비상 모달 제공이 아닌 한 재검색 과정 내내 표시).
- **[필수]** 사용자가 설정한 상세 검색 조건을 유지한다(의도적으로 해제하기 전까지).
- **[권장]** 상세 검색 조건의 적용을 일괄적으로 해제할 수 있는 수단을 제공하고 직관적으로 인지할 수 있도록 표현한다.

### 7. 검색 종료

- **[필수]** 검색 과업 맥락에서 벗어나 다른 화면 또는 다른 탐색 수단에 빠르게 접근할 수 있도록 한다. 검색 결과 화면에도 메인 메뉴, 사이트맵 같은 탐색 인터페이스를 제공해야 한다.
