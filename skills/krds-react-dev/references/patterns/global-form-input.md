# 입력폼

## 개요

입력폼은 사용자가 데이터를 입력하여 서버로 전송하는 데 사용하는 콘텐츠 섹션으로 하나 이상의 입력 컨트롤로 구성된다.

## 구조

1. **제목** — 입력폼의 목적에 대한 설명
2. **설명(선택)** — 부가적인 설명이나 입력 시 유의 사항 등 총체적인 안내
3. **콘텐츠** — 데이터 입력을 위한 컴포넌트의 모음
4. **필드셋(선택)** — 서로 관련된 여러 입력 컴포넌트를 의미적으로 그룹화
5. **오류 메시지** — 데이터 입력 오류 발생 시 제공되는 피드백 메시지
6. **액션 버튼** — 데이터 전송 또는 입력값/프로세스 중단을 위한 버튼 그룹

## 유형

| 유형 | 설명 |
| --- | --- |
| 단일 화면에서의 데이터 입력 | 가장 기본적인 유형. 1개 이상의 폼 콘텐츠로 구성. 점진적 공개법(Progressive disclosure)으로 단계 이동 없이도 복잡성을 줄일 수 있다 |
| 모달을 활용한 데이터 입력 | 매우 중요하고 빈번하지 않은 데이터 입력에 적합. 모달 내 입력 관련 컴포넌트는 5개 이내로 구성 권장 |
| 단계별 데이터 입력 | 데이터가 복잡하거나 중간 저장이 필요한 경우 여러 화면에 단계별로 제공. 단계는 명확하게, 각 단계 내 콘텐츠는 논리적·선형적 관계를 가져야 하며 완수/진행률 표시 컴포넌트가 필요. 과업 숙달 사용자에게는 비효율적일 수 있으므로 먼저 콘텐츠 섹션 구분·헤딩 강조·콘텐츠 간결화를 시도해야 한다 |

## 사용성 가이드라인

- **콘텐츠는 가능한 한 하나의 열에 수직으로 정렬한다.** 여러 열 그리드는 콘텐츠 간 관계를 오인하기 쉽다. 단, 입력받을 데이터가 많고 폼 너비가 충분하거나 성/이름, 전화번호, 신용카드 번호, 우편번호/주소, 시작·종료 일자처럼 의미적으로 관련된 컴포넌트는 한 열에 수평으로 배치할 수 있다.
- **입력폼과 입력폼, 콘텐츠와 콘텐츠 사이에 충분한 간격을 제공한다.** 너무 가까우면 사용자가 혼동할 수 있다.
- **액션 버튼은 일관된 위치에 배치하고 정렬한다.** 오른쪽 하단 가장자리 배치를 권장하며, 제출 버튼이 가장 오른쪽에, 다음 순위 버튼이 순차적으로 왼쪽에 배치된다. 3개 이상의 동작이 필요하면 3차 동작 버튼은 폼의 왼쪽 하단 가장자리에 배치해 구분한다(이 경우 왼쪽 정렬 순서는 반대이며 제출 버튼이 가장 왼쪽).
- **비활성화 상태의 콜투액션 버튼 사용을 고려한다.** 필수 항목이 모두 입력되기 전까지 제출/다음 단계 버튼을 비활성화하면 제출 요건 미충족을 직관적으로 인지시킬 수 있다. 제출 시 중복 제출 방지를 위해 버튼을 비활성화하고, 처리 시간이 걸리면 피드백 메시지·인디케이터(스피너 등)로 처리 중임을 안내한다.
- **입력 필드 주변에 레이블과 설명을 제공한다.** 용도와 관련 도움말을 근접한 위치에 제공한다.
- **입력값의 단위를 표시한다.** 레이블과 별개로 '개', '부수' 등 단위를 표시해 입력 오류를 줄인다.
- **필수 입력 항목과 선택 입력 항목을 명확하게 구분한다.** 시각적 노이즈와 혼동을 최소화해야 한다. 전체 항목 대비 필수/선택 항목 수를 고려해, 대부분이 필수면 선택 항목만 표시하고 대부분이 선택이면 필수 레이블만 표시한다.
- **필수 또는 선택 입력 항목은 일관성 있는 방식으로 구분한다.** 동일한 유형의 폼 또는 전체 웹사이트에서 일관되어야 한다 — 레이블에 '필수'/'선택' 텍스트 표시, 필수 항목에 별표 표시, 모든 콘텐츠가 필수인 경우 폼 상단 안내 텍스트 중 하나를 활용할 수 있다.
- **사용자로부터 최소한의 데이터만 입력받는다.** 반드시 필요한 정보만 입력하도록 콘텐츠를 간결화하고 입력 항목을 신중히 도출해야 한다.
- **사용자가 자주 입력하는 데이터에 자동 완성 기능을 제공하는 방안을 고려한다.** 로그인 상태면 회원 정보를 자동 호출하거나, 직전 입력 정보를 재사용하는 옵션, `autocomplete` 속성 활용을 고려한다.
- **사용자가 잘못 입력/선택한 값을 자동으로 삭제하지 않는다.** 사용자가 문제를 확인하고 수정할 수 있도록 한다.

## 플랫폼에 대한 고려 사항

**모바일을 염두에 두고 디자인해야 한다.** 터치스크린 환경과 대역폭이 제한된 환경에서 양식을 제공할 수 있는 방법을 고려한다.

## 접근성 가이드라인

- **각 입력 필드와 입력폼에 이름을 제공한다.** 스크린 리더에서 각 입력 요소에 접근 가능한 이름이 필요하다. 관련: KWCAG 2.2 레이블 제공, WCAG 2.1 Info and Relationships(A)/Name, Role, Value(A).
- **입력폼 각 섹션에 제목을 제공한다.** 헤딩 태그를 사용해 스크린 리더 사용자가 섹션 구조를 인지하고 섹션 단위로 건너뛸 수 있도록 한다. 관련: KWCAG 2.2 제목 제공, WCAG 2.1 Info and Relationships(A)/Labels or Instructions(A).
- **어떤 항목에서 오류가 발생했는지에 관한 정확한 정보를 오류 메시지로 알려주어야 한다.** 서버 측 검증이면 확인 버튼을 누른 후 초점을 오류 항목으로 이동시켜야 한다. 관련: KWCAG 2.2 오류 정정, WCAG 2.1 Error Identification(A)/Status Messages(AA).
- **사용자가 입력 필드의 초점을 자유롭게 이동시킬 수 있도록 제공한다.** 입력 완료 시 초점을 자동으로 다음 필드로 이동시키더라도 이전 항목으로 돌아갈 수 있어야 한다. 관련: KWCAG 2.2 초점 이동과 표시, WCAG 2.1 Focus Order(A).
- **필수 입력 항목 정보는 보조 기술이 확인할 수 있는 형태로 제공한다.** 이미지로 표시했다면 대체 텍스트를 제공해야 한다. 관련: KWCAG 2.2 적절한 대체 텍스트 제공, WCAG 2.1 Non-text Content(A)/Labels or Instructions(A).
- **단계가 있는 입력폼에서 반복적으로 입력해야 하는 정보를 자동 입력하거나 동일하게 입력할 수 있는 수단을 제공한다.** 이전 단계 입력 정보를 자동 입력하거나 재사용 선택 버튼을 제공한다. 관련: KWCAG 2.2 반복 입력 정보.

## 상호작용 가이드라인

입력폼은 필수 항목 입력 여부와 데이터가 정해진 양식·규칙에 적합한지를 확인해 부적합한 입력에 피드백을 제공해야 한다. 클라이언트 측 검증과 서버 측 검증을 함께 사용한다.

클라이언트 측 검증은 서버 전송 전 브라우저에서 실시간으로 확인해 오류 항목에 인라인 메시지를 제공한다. 직관적 인지·수정과 서버 부하 감소 측면에서 권장되지만, 쉽게 지나칠 수 있고 보안 측면을 검증하지 않으므로 서버 측 검증이 반드시 함께 필요하다. 서버 측 검증 피드백도 오류 발생 항목에 인라인으로 제공하는 것이 바람직하다.

**클라이언트 측 검증**

| 이벤트 | 적용 상황 |
| --- | --- |
| Keyup | 아이디 중복 확인, 비밀번호 작성 규칙처럼 텍스트 입력 중 실시간 검증이 필요한 경우 — 타이핑 중 값을 검증 |
| Focusout | 날짜처럼 전체 값이 입력되기 전까지 적합성을 판단하기 어려운 경우 — Keyup마다 검증하면 방해가 되므로, 모든 값 입력 후 다음 항목으로 이동을 시작했을 때 메시지 제공 |

**서버 측 검증**

| 조작 | 동작 |
| --- | --- |
| Click | 폼 제출 클릭 시 오류가 발생한 첫 번째 항목으로 Focus 이벤트 발생 |
| Enter | 제출 버튼에 초점이 있는 상태에서 Enter 시 동일하게 첫 오류 항목으로 Focus 이벤트 발생 |

## 관련 KRDS 컴포넌트

| 컴포넌트 | 비고 |
| --- | --- |
| TextInput | 텍스트 데이터 입력(이름, 전화번호, 우편번호 등) |
| Textarea | 장문 텍스트 입력 |
| Select | 옵션 선택 |
| Dropdown | 옵션 선택(콤보박스형) |
| Checkbox | 다중 선택, 필수/선택 항목 등 |
| Radio | 단일 선택(발급 유형 등) |
| DateInput | 날짜 입력(시작/종료 일자 등) |
| ToggleSwitch | 온/오프형 선택 |
| Button | 액션 버튼(제출, 취소 등) |
| Spinner | 제출 처리 중 인디케이터 |
| StepIndicator | 단계별 데이터 입력의 진행률 표시 |
| ContextualHelp | 도움말(예시의 "도움말" 버튼) |
