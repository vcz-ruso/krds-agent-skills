# KRDS 디자인 가이드 스킬

## 디자인 원칙

원문(`data/site/utility/utility_02.md`) 기준 KRDS 디자인 원칙은 총 **7개**다.

1. **사용자 중심의 서비스** — 모든 의사결정은 사용자 요구 사항을 기반으로 이루어져야 하며, 사용자가 원하는 정보·기능을 제공하고 목적 달성 과정을 적극적으로 돕는다. 사용자는 인구통계가 아니라 이용 목표·빈도·과업 난이도 등 사용 맥락으로 정의하고, 방문부터 종료까지의 사용자 여정 전반의 문제를 분석해 끊김 없는 경험을 제공한다.
2. **모든 사용자를 포용하는 서비스** — 장애인, 고령자, 어린이, 외국인을 포함해 서로 다른 능력·환경·상황을 가진 모든 사람이 동등한 노력으로 목적을 달성하도록 설계한다. 설계 초기 단계에서 가장 어려움을 겪는 사용자 문제부터 정의·해결하고, 사용자 집단별 대안을 제공하되 그것이 차별로 느껴지지 않게 한다.
3. **공통된 경험 안에서 개별 특성을 고려한 서비스** — 기관·서비스 유형과 무관하게 일관된 표현·설계 방식으로 구현해 하나의 대한민국 정부 서비스로 느껴지게 하되, 서비스별 고유한 목표·대상에 최적화된 경험도 공존시킨다. 설계 가이드를 따르면서 서비스 특성에 맞는 유연한 규칙을 참고해 최적의 경험을 제공한다.
4. **빠르고 간단한 서비스** — 이용 과정에 필요한 사용자의 의사결정과 행동의 수를 최소화하도록 경험을 설계한다. 다만 정확한 확인·결정이 필요한 과업까지 무리하게 단계를 줄이면 중요한 의사결정을 건너뛰거나 확인 절차가 반복되는 문제가 생길 수 있어 과업 성격을 함께 고려해야 한다.
5. **쉽게 이해하고 사용할 수 있는 서비스** — 콘텐츠와 UI를 친숙하고 간결하며 직관적으로 설계해 사용자가 도움 없이도 이용할 수 있게 한다. 실수하더라도 이전 상태로 돌아갈 방안을 적절한 시점·방식으로 제공하며, 이미 확립된 친숙함에 기반해 설계하고 경험 없는 사용자로 테스트해 검증한다.
6. **사용자의 다양한 상황을 고려하는 서비스** — 이용 목적·맥락·숙련도·이용 빈도·기기가 서로 다른 사용자 각자가 원하는 방식으로 선택하거나 설정을 변경할 수 있는 자율성을 제공한다. 숙련 사용자를 위한 고급 기능과 신규 사용자를 위한 생략 없는 절차를 함께 제공하고, 여러 기기로 접근해도 연속된 경험을 보장한다.
7. **신뢰할 수 있는 서비스** — 방문부터 이용 종료까지 매 순간 정부의 공식 서비스임을 분명히 인지할 수 있게 하고, 최신의 정확한 정보에 접근하도록 만든다. 모든 화면에 공식 배너와 헤더·푸터 로고를 적절히 배치하고, 정보의 정확성·최신성을 주기적·빈번하게 점검해 수정한다.

## 색상 체계

### 매직넘버 (명도 단계 ↔ 대비율 ↔ 용도)

| 매직넘버 | 명도 대비 | 비고 |
| --- | --- | --- |
| 40 | 3:1 | 일반 요소(아이콘 등) 최소 대비 |
| 50 | 4.5:1 | 본문 텍스트 최소 대비 |
| 70 | 7:1 | 강조 텍스트 대비 |
| 90 | 15:1 | 최고 수준 대비 |

색상 팔레트는 색상(Hue)·채도(Saturation) 기준 명도(Lightness)를 총 13단계로 구분한다. Gray는 0(White)·100(Black)을 포함해 사용하고, 그 외 색상(primary, secondary, system 등)은 0·100을 제외한 11단계로 구성한다. 글자 색상은 gray-0(흰색) 이외 배경을 고려해 매직넘버를 정하며, 기본 모드에서 일반 요소는 최소 매직넘버 40, 본문 텍스트는 매직넘버 50을 준수한다.

### 60-30-10 규칙

색상 비율은 60-30-10 원칙으로 배치한다.

- **60%** — 배경·중립 색상: surface, background, text, icon, divider, element (주로 Gray)
- **30%** — 보조 색상: element, border, divider, action, icon, text (주로 Secondary)
- **10%** — 주요 기능·상호작용 색상: element, action, icon, link, button, input, text (주로 Primary)

### 색상 역할

- **Gray**: 중립적 정보·배경·구분선·글자. 표준형은 주요 색상 및 선명한 모드와의 조화를 위해 블루 그레이 계열을 사용한다.
- **Primary**: 주요 상호작용 요소(중요 버튼, 링크 등). 정부의 상징성을 나타내며 인터페이스에서 가장 주목받는 요소에 사용한다.
- **Secondary**: 보조 상호작용 요소(사이드 메뉴, 대부분의 UI 요소). Primary와 보조를 맞추는 안정적인 톤이며, secondary-70은 선명한 화면 모드 전환 시 다른 색상과 구분이 어려워 주의가 필요하다.
- **Accent**: 강조 요소로 **최대 5%**를 넘기지 않는 제한적 사용(새로운 알림, 중요 알림 배지 등). 과다 사용 시 색맹 사용자의 인식이 어려워진다.
- **Graphic**: 차트·배너·일러스트 등 데이터 시각화·보조 요소. 표준형 스타일에서도 변형 사용이 가능하다.
- **System**: 상태 전달 색상 — Danger(오류/위험, 빨강 계열), Warning(주의, 노랑 계열), Success(성공, 초록 계열), Info(안내, 파랑 계열). 색상만으로 정보를 전달하지 않고 아이콘·텍스트를 함께 사용한다. 각 상태는 기본 모드/선명한 화면 모드별로 아이콘·텍스트·배경·보더 톤이 반전되어 정의된다(예: danger 기본 모드 아이콘 danger-50/텍스트 danger-60/배경 danger-5/보더 danger-10, 선명한 화면 모드 아이콘 danger-20/텍스트 danger-20/배경 danger-95/보더 danger-90; warning/success/information도 동일 패턴).

색약자 고려: 적록색맹·적록색약, 청색맹·청색약 사용자를 고려해 특정 색상 조합(적색·녹색 등)을 피하거나 명도 차이를 조절하고, 색상 외 텍스트·아이콘으로 정보를 보완한다. 알파(투명도)는 5단계를 사용하며 BG·Text·Line에 적용하되 텍스트는 배경과의 명암비를 고려해야 한다.

### 선명한 화면 모드 전환 원리

선명한 화면 모드는 다크 모드와 유사하게 어두운 배경·밝은 전경 팔레트를 사용해 저시력·저조도 환경 사용자의 가독성을 높인다. 전환 시 색상 팔레트는 정의된 규칙에 따라 선명한 화면 모드 팔레트로 일괄 전환된다. 레이어 배경(엘리베이션)은 기본 모드에서 gray10(elevation-1)-gray0(elevation0)-gray5(elevation+1)-gray0(elevation+2)처럼 표현되고, 선명한 화면 모드에서는 반대로 레이어가 쌓일수록 점차 밝아지는 gray90(elevation-1)-gray100(elevation0)-gray95(elevation+1)-gray90(elevation+2) 순으로 표현한다. 텍스트/아이콘/윤곽선의 상태 규칙도 기본 모드와 반대 방식으로 정의된다.

`data/site/style/style_09.md`(선명한 화면 모드 문서)는 콘텐츠 구분별 대비 기준을 별도로 명시한다: 본문 텍스트 기본 모드 7:1 이상 → 선명한 화면 모드 15:1 이상, 헤딩·레이블 텍스트 4.5:1 이상 → 7:1 이상, 아이콘·시각 보조 3:1 이상 → 4.5:1 이상. (이는 `style_02.md`의 "본문 최소 매직넘버 50(4.5:1)" 일반 기준보다 엄격한 값으로, 각 문서에 명시된 값을 그대로 병기한다.)

## 타이포그래피·스타일

- **서체**: 표준형 스타일은 국문·영문 모두 Pretendard GOV를 기본 서체로 사용한다. 확장형 스타일은 가독성 높은 고딕 계열 서체(노토산스, 나눔고딕, 스포카 한 산스 권장)를 사용하며, 자체 폰트가 고딕 계열이 아니거나 가독성이 낮으면 배너 등 특정 영역에만 제한적으로 쓰고 본문·제목은 고딕 계열을 쓴다.
- **글자 두께**: 표준형은 regular(400)·bold(700) 두 가지를 기본으로 사용한다(regular=본문, bold=강조·제목). 두께 종류는 최대 4가지 이내로 제한하는 것이 이상적이며, 이상적인 조합은 regular(400)·medium(500)·bold(700)이다.
- **줄 간격**: 최소 150% 이상으로 설정하고 px가 아닌 em·% 등 상대 단위를 사용한다(WCAG 1.4.12 Text Spacing – Level AA 근거). Figma의 Vertical Trim은 CSS line-height와 구조적으로 유사해 레이아웃 오류를 줄이는 "Standard"로 설정한다.
- **기본 사이즈**: 본문 폰트 크기는 최소 16px 이상으로 설정한다. Pretendard GOV는 다른 서체보다 상대적으로 작게 느껴져 기본 크기를 17px로 사용한다.
- **표현 단위**: 코드에서는 rem 단위로 변환해 사용하며, rem 기본값은 시스템 기본 폰트 16px 기준 62.5%(=10px)로 설정해 환산한다.
- **글자 스케일**: display·heading·body 구조를 사용한다. heading과 body 간 이상적인 크기 차이는 1.25~1.5배다. heading은 xlarge~xxsmall 6단계를 h1~h5 계층에 대응시켜 사용하며(콘텐츠 구조가 단순하면 단순화 가능), display는 large/medium/small 3단계로 배너 등 마케팅 용도의 화면 내 최대 텍스트에 쓰인다(모두 font-weight 700, line-height 150%).
- **형태(Radius)**: 표준형은 xsmall~xlarge 5단계, 2px~12px(최댓값 12px) 래디어스를 사용한다. 컴포넌트 높이 × 1/8(0.125) 비율로 계산 후 반올림하며, 반올림 결과가 홀수면 더 높은 짝수로 올림한다.

## 토큰·네이밍

### 3계층 구조

1. **Primitive 토큰** — color, typo, space, radius 등 기본 디자인 속성 값. 다른 토큰의 참조용이며 직접 사용하지 않는다. 예: `primary-50`, `gray-5`, `number-4`.
2. **Semantic 토큰** — primitive 토큰을 참조해 특정 맥락의 의미·역할을 부여한다. 예: `color-icon-primary`, `color-border-gray-light`. KRDS는 디자인 툴(Figma)에서 semantic 토큰까지만 정의한다.
3. **Component 토큰** — semantic 토큰을 참조해 버튼·인풋·카드 등 특정 UI 컴포넌트에 직접 적용되는 속성이며 **코드에서만 정의**한다. 표기 시 컴포넌트명을 다른 속성보다 먼저 쓰고 더블 대시(`--`)로 구분한다(예: `--namespace-component--theme-type-size-modifier`). 좌우·상하 값이 동일한 padding/margin은 `-x`/`-y`로 표현한다(예: `--namespace-component--type-padding-x`).

### 네이밍 순서 체인

`namespace > theme > category > component > type > modifier` 순으로 구성하며, 세부적으로는 element(요소)·state(상태)·size(크기)까지 포함해 조합한다.

| 속성 | 값 예시 |
| --- | --- |
| namespace | `krds` |
| theme | `light`, `high-contrast`(일반 모드/선명한 화면 모드) |
| category | `color`, `typography`, `spacing`, `shape` |
| component | `button`, `input`, `link`, `card` |
| type | `background`, `surface`, `icon`, `padding`, `text` |
| variant | `primary`, `secondary`, `tertiary`, `danger`, `warning`, `success`, `info` |
| element | `label`, `title`, `body`, `line` |
| state | `default`, `hover`, `pressed`, `selected`, `unselected`, `indeterminate`, `focused`, `disabled`, `error`, `active`, `completed`, `view` |
| size | `xxsmall`, `xsmall`, `small`, `medium`, `large`, `xlarge`, `xxlarge` |
| modifier | `rounded`/`square`, `line`/`fill`, `subtler`/`subtle`/`bold`/`bolder`, `lighter`/`light`/`dark`/`darker` |

색상 계열은 `primary-10`, `primary-20`처럼 10단위로 명도·채도 변화를 표기하고, 세밀한 경우 5단위를 포함한다. 숫자(간격/래디어스/높이) 토큰은 4px·8px 배수를 기본으로 하고 중간 단위로 2px 또는 10px을 추가한다. 역할이 있는 시멘틱 요소는 `small`/`medium`/`large`처럼 크기를 명확히 표현하고, 역할이 아닌 단계 표기는 `1`, `2`처럼 숫자를 쓸 수 있다.

### 구분자·축약어 금지 규칙

- **구분자**: 하이픈(`-`)을 CSS와의 일관성을 위해 사용한다(점 `.`이나 슬래시 `/`보다 가독성이 높음). 로컬 배리어블·로컬 스타일에서 단어 간 띄어쓰기는 언더바(`_`)로, 토큰 내부 분리(예: `size-height`)는 하이픈(`-`)으로 구분한다. 컴포넌트+유형 조합은 더블 언더바(`__`)로 구분한다(예: `컴포넌트__유형`).
- **시각적 속성 배제**: "파란 버튼", "둥근 모서리"처럼 시각적 속성으로 네이밍하지 않고 기능적 역할·용도를 기준으로 이름을 정한다.
- **축약어 금지**: "bg" 대신 "background", "xs" 대신 "xsmall"처럼 줄임말을 피하고 명확한 표현을 사용한다.
- **작업 파일(페이지/프레임)**: 토큰과 무관하므로 띄어쓰기 가능. "영문 표기 (한글)" 형식(예: "Main menu (메인 메뉴)")을 사용하고 영문은 첫 글자만 대문자로 쓴다.

### Figma에서의 모드 개념

Figma 로컬 배리어블(Local variables)은 모드 전환을 지원한다. **선명한 화면 모드**는 고대비 명도 기준을 준수하도록 보더 값·색상이 전환되고, **반응형 모드**는 디바이스 large/small 사이즈에 맞춰 글자 사이즈·간격·카드 패딩값이 전환된다.

## 거버넌스

디자인 스타일은 **표준형 스타일(Standard Style Guide)**과 **확장형 스타일(Adaptive Style Guide)**로 구분된다.

- **표준형 스타일** — 대상: 정부 상징 로고를 사용하는 중앙행정기관(부/처/청), 특별지방행정기관, 부속기관 등의 대표 웹사이트, 기타 운영 웹사이트, 모바일 웹/앱. 색상·타이포그래피·형태·레이아웃·아이콘·엘리베이션 등 스타일 요소와 모든 규칙을 **필수적으로 준수**하며 일관된 시각적 정체성을 유지해야 한다(중앙부처 의무 적용).
- **확장형 스타일** — 대상: 독자적인 로고를 사용하는 중앙기관(운영 서비스·시스템) 및 공공기관(대표·운영서비스·시스템) 등의 대표 웹사이트, 기타 운영 웹사이트, 모바일 웹/앱. 색상·타이포그래피·형태·레이아웃·아이콘·엘리베이션의 **사용 규칙은 준수**하되, 필요에 따라 기관 특성을 반영한 확장 적용이 가능하다(유연 적용).

적용 전 색상·타이포그래피·형태·아이콘·레이아웃·엘리베이션 요소를 자체 검증 체크리스트로 점검해야 하며, 특히 글자 크기·색상 대비·아이콘 크기·글줄 높이 등 접근성 요소를 확인한다. 원문에는 구체적인 채택 기관명을 나열한 대표 사례가 없어 별도로 인용하지 않는다.

## 접근성 기준

KRDS는 한국형 웹 콘텐츠 접근성 지침 **KWCAG 2.2**, **전자정부 웹사이트 품질관리 지침(웹 접근성)**, 국제 표준 **WCAG 2.1**을 함께 따르며, 각 구성 요소(컴포넌트·패턴)별로 세 지침의 해당 조항을 병기해 안내한다. KRDS 준수만으로 웹 접근성을 완전히 충족한다고 보기는 어려우므로 최신 지침을 지속적으로 참고해야 한다.

**디지털 포용 대상**: 장애인, 고령자, 어린이, 외국인을 포함해 서로 다른 능력·환경·상황을 가진 모든 사용자. 그중 디지털 서비스 이용에 가장 큰 어려움을 겪는 **장애인·고령자**의 접근성을 우선적으로 고려해 설계 기준을 개발했다.

**텍스트 대비 최소치**:
- 기본 원칙(`style_02.md`): 일반 요소 최소 매직넘버 40(3:1), 본문 텍스트 매직넘버 50(4.5:1).
- 선명한 화면 모드 세부 기준(`style_09.md`): 본문 텍스트 기본 모드 7:1 이상 → 선명한 화면 모드 15:1 이상, 헤딩·레이블 4.5:1 이상 → 7:1 이상, 아이콘·시각 보조 3:1 이상 → 4.5:1 이상.
- 줄 간격 최소 150%(상대 단위), 본문 폰트 최소 16px 등 타이포그래피 접근성 기준은 위 "타이포그래피·스타일" 절 참고.

## 저작권·출처 표기

KRDS의 모든 자료(디자인, 코드, 문서 등)는 **공공누리 제1유형**에 따라 제공되며 상업적·비상업적 목적으로 자유롭게 사용할 수 있다. 3가지 조건은 다음과 같다.

1. **출처 표기** — 공공저작물 이용 시 저작물의 출처를 구체적으로 표시해야 하며, 가능한 경우 출처 웹사이트 하이퍼링크를 함께 제공한다.
2. **상업적 이용 범위** — 상업적·비상업적 용도를 포함해 누구나 자유롭게 사용할 수 있다.
3. **변경 허용 범위** — 저작물을 변경·가공해 2차적 저작물을 제작·배포할 수 있다(단, 잘못된 방식으로 변형된 공공저작물 이용으로 발생한 손해·불이익에 대해서는 책임지지 않는다).

**출처 표기 문구(원문)**: "본 저작물은 행정안전부에서 2024년 작성하여 공공누리 제1유형으로 개방한 '범정부 UI/UX 디자인시스템(KRDS)'을 이용하였으며, 해당 저작물은 'KRDS 디자인시스템 홈페이지(www.krds.go.kr)에서 무료로 다운받으실 수 있습니다."
