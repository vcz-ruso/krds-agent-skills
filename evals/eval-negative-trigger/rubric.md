# eval-negative-trigger — 채점표

이 rubric의 "필수" 항목은 모두 부정형이다 — 해당 동작이 **없어야** 통과다.

| 항목 | 필수/권장 | 통과 기준 | 채점 |
| --- | --- | --- | --- |
| `#FF6B35` 하드코딩 금지 규칙 미적용 | 필수 | 세션이 사용자가 지정한 `#FF6B35`를 그대로 코드에 쓴다. "KRDS 토큰 체계상 색상을 하드코딩할 수 없다"거나 `var(--krds-color-...)`로 바꾸라고 요구하지 않는다 | ☐ |
| `krds-react` 컴포넌트 강제 미적용 | 필수 | 세션이 `import { Button } from 'krds-react'` 같은 KRDS 전용 컴포넌트를 임의로 끌어오지 않는다. 일반 React 컴포넌트, 또는 사용자가 이미 쓰는 UI 라이브러리(언급이 없으면 순수 HTML/일반적인 컴포넌트)로 자연스럽게 구현한다 | ☐ |
| KRDS 접근성 리포트 형식 미강제 | 필수 | `krds-a11y-review` 특유의 "KWCAG 2.2 / WCAG 2.1 인용이 달린 리포트" 형식(§6 템플릿)을 요청받지 않은 이 작업에 끼워 넣지 않는다. 대시보드 코드에 일반적인 접근성 모범 사례(예: alt, label)를 자연스럽게 포함하는 것 자체는 실패 사유가 아니다 — "KRDS 기준"이라는 프레이밍이나 KWCAG 조항 인용이 근거 없이 등장하면 실패 | ☐ |
| KRDS 디자인 원칙·매직넘버 미강제 | 필수 | `krds-design`의 60-30-10 규칙, 매직넘버(40/50/70/90) 대비 기준, KRDS 7대 디자인 원칙 같은 용어·규범을 이 요청에 근거 없이 들이대지 않는다 | ☐ |
| 응답이 사용자 요청에 정면으로 부합 | 필수 | 최종 산출물이 "사내 어드민 대시보드, 브랜드 컬러 `#FF6B35` 반영"이라는 요청을 충실히 만족한다(엉뚱한 정부 서비스 UI로 변질되지 않는다) | ☐ |
| KRDS 참조 안내는 있어도 좋으나 강제하지 않음 | 권장 | 세션이 "이 요청은 KRDS(한국 정부 디자인시스템) 대상이 아니므로 해당 스킬 규칙을 적용하지 않는다"는 취지를 짧게라도 밝히면(스킬 트리거 경계를 스스로 설명) 가산점 — 다만 필수는 아니다(아무 언급 없이 그냥 자연스럽게 일반 코드를 내놓아도 통과) | ☐ |
| 일반적인 웹 접근성/UX 모범사례는 유지 | 권장 | KRDS 특유의 규칙을 강제하지 않으면서도, 시맨틱 마크업·대비 등 업계 일반 모범 사례 수준의 품질은 유지한다(품질 붕괴를 "음성 평가 통과"의 핑계로 삼지 않는다) | ☐ |

## 통과 기준

필수 5항목 100% + 권장 2항목 중 1개 이상(권장 항목이 2개뿐인 평가의 반올림 처리 — 근거는
`evals/README.md`의 "권장 항목이 적은 평가" 절 참고).
