# 필터링·정렬

## 개요

필터링·정렬은 데이터 집합에서 사용자가 원하는 속성과 범주에 속하는 데이터 항목을 선별적으로 표시하거나 특정 속성/범주를 기준으로 조직화하는 방법이다. 필터링·정렬을 이용하면 데이터 목록에서 탐색할 범위를 좁힐 수 있기 때문에 검색 결과 등 목록을 탐색하여 원하는 정보를 찾는 시간을 줄일 수 있다.

## 구조

1. **정렬 컨트롤** — 정렬 조건 설정을 위한 입력 양식과 레이블의 모음
2. **필터 컨트롤** — 필터 조건 설정을 위한 입력 양식과 레이블의 모음(기본 노출 또는 상세 필터 버튼으로 활성화)
3. **적용된 필터링 조건** — 적용된 조건, 조건 수, 해당 데이터 항목 개수, 개별 조건 해제 버튼
4. **적용된 필터링 조건 해제 버튼** — 모든 조건을 일괄 해제

## 유형

**필터링 방식**

| 방식 | 설명 |
| --- | --- |
| 텍스트 필터 | 검색과 유사하게 특정 단어를 포함하는 정보를 조회하는 가장 기본적인 방식 |
| 스코프 필터 | 텍스트 필터 좌/우에 배치되어 검색할 정보 유형의 범위를 셀렉트 옵션으로 제한 |
| 선택형 필터 | 데이터 속성을 선택해 특정 속성에 속하는 정보 확인. 속성별 단일 또는 다중 옵션 선택 가능 |
| 범위 필터 | 정량적 데이터·날짜 범위 조회. 슬라이더, 날짜 범위 입력 컴포넌트로 제공 |
| 쿼리 필터 | 여러 속성·옵션에 AND 외 다양한 연산 조건 적용. 매우 복잡한 데이터 집합에 적합 |
| 관계형 필터 | 데이터 속성 간 관계·위계 구조 표현. 한 속성의 선택에 따라 다른 속성 옵션이 달라지는 경우 적합 |

**정보 조회와 표시**

| 방식 | 설명 | 적합한 상황 |
| --- | --- | --- |
| 즉각 표시 | 옵션 선택 즉시 필터링·정렬·조회 실행 | 속성 1~2개만 필터링, 조회 속도가 빠른 경우 |
| 일괄 표시 | '조회하기'/'적용하기' 등 확정 행동 후 실행 | 옵션 선택에 시간이 걸리는 복잡한 목록, 조회 속도가 느린 경우 |

**레이아웃**

| 레이아웃 | 설명 |
| --- | --- |
| 수평 막대 | 목록 상단에 얇고 긴 막대. 실행 시 드롭다운으로 상세 옵션 표시 |
| 인라인 | 데이터 목록 자체 또는 열 헤더에 직접 표시. 수직 공간 절약, 충분한 너비가 필요. 한 번에 하나의 속성만 정렬 가능해 단순한 행동에 적합 |
| 사이드 패널 | 목록 그리드 좌/우에 필터링 컨트롤을 수직 배치(정렬은 대개 별도로 목록 상단 수평 막대). 필터링 옵션과 목록을 한 화면에서 비교 가능 |
| 모달 | 필터링 조건 전체/일부를 별도 모달에 제공. 고급 옵션이거나 화면 너비가 부족한 경우 사용 |

## 사용성 가이드라인

- **필터링·정렬 컨트롤을 가능한 한 숨기지 않는다.** 화면 너비가 충분하면 주요 옵션이 항상 노출되도록 해 조건 변화에 따른 결과를 함께 비교할 수 있게 한다.
- **선택된 필터링·정렬 옵션이 명확하게 구분되도록 표현한다.** 라디오 버튼, 체크박스, 셀렉트 등 관련 컴포넌트 가이드라인을 참고한다.
- **조건이 적용되었음을 확인할 수 있는 명확한 시각적 단서를 제공한다.** 데이터 집합 목록이 변경된 상황을 빠르고 직관적으로 인지할 수 있게 한다.
- **모든 필터링·정렬 컨트롤에 레이블과 그룹 헤딩을 제공한다.** 생략하면 어떤 속성의 옵션인지 인지하지 못할 수 있다.
- **필터링·정렬 컨트롤 레이블은 이해가 쉽도록 간결하고 정확한 내용으로 제공한다.** 서술형 레이블, 전문 용어·축약어는 빠른 인지를 방해한다.
- **필터링 컨트롤은 우선순위에 따라 좌측 또는 상단부터 순차적으로 배치한다.** 빈번하게 사용되거나 핵심적인 속성은 접근하기 쉬운 영역에 배치한다.
- **관련 있거나 유사한 필터링 컨트롤을 군집화하여 제공한다.** 예: 지역을 '도', '시', '군/구' 단위로 나눈 세 컨트롤은 연속 배치한다.
- **인라인 형식의 정렬을 사용할 때를 제외하고 정렬 컨트롤은 대상 목록 오른쪽 상단에 배치한다.** 일관된 사용자 경험을 위해서다.
- **필터링 옵션으로 제공되는 메타 데이터가 색인화되고 검색 가능한지 확인한다.** 옵션 선택 시 적절한 데이터가 반환되는지 정기 점검하고, 이용되지 않거나 더 이상 존재하지 않는 속성은 옵션에서 삭제하는 방안을 검토한다.
- **데이터 집합의 특성과 사용자의 요구사항에 적합한 수준의 필터링·정렬 옵션을 제공한다.** 지나치게 세분화하면 압박·혼란을 줄 수 있으므로 결과를 좁히는 데 도움이 되는 핵심 속성 중심으로 제공하고 필요한 옵션을 추가한다.
- **날짜, 시간을 기준으로 한 필터링은 범위를 입력할 수 있도록 제공한다.** 단일 날짜만 설정 가능하면 조건을 여러 번 설정해야 한다.
- **적용된 필터링 옵션을 한 번에 해제할 수 있는 기능을 제공한다.** 3개 이상의 속성에 필터링 컨트롤이 제공되는 경우, 옵션을 하나씩 해제하는 반복 동작이 없도록 일괄 해제 기능을 제공해야 한다.

## 플랫폼에 대한 고려 사항

**모든 필터링·정렬 컨트롤을 표시하기에 화면 너비가 충분하지 않은 경우, 필터링 및 정렬 컨트롤 버튼을 축약하여 제공한다.** 컨트롤 버튼은 목록의 우측 상단에 배치하며, 필터 컨트롤이 먼저 배치되도록 한다.

## 접근성 가이드라인

- **조건이 적용되었음을 확인할 수 있는 명확한 프로그램적 단서를 제공한다.** 전체 검색 결과 수 안내 텍스트에 live-region을 적용하고, 값 변경 즉시 스크린 리더로 전달되도록 `aria-live="polite"`를 사용해야 한다. 관련: WCAG 2.1 Name, Role, Value(A)/Status Messages(AA).
- **정보 조회가 완료된 이후 키보드 초점이 적절한 요소에 유지되도록 한다.** 즉각 표시는 초점을 값을 변경/선택한 옵션 요소에, 일괄 표시는 제출 버튼에 유지한다. 예측할 수 없는 요소로 초점이 이동하면 부가적인 탐색 과정이 필요해진다. 관련: KWCAG 2.2 초점 이동과 표시, WCAG 2.1 Focus Order(A).

## 상호작용 가이드라인

- **즉각 표시**: 옵션 값을 선택하거나 값이 변경되면 즉시 조회/정렬이 발생한다.
- **일괄 표시**: '적용'/'조회' 버튼에서 Enter/Space Keyup 또는 Click 이벤트 발생 시 설정한 옵션이 일괄 적용된다.
- **인라인 정렬 — 컨트롤 탐색**: 모든 정렬 버튼은 Tab/Shift+Tab으로 접근할 수 있어야 한다.
- **인라인 정렬 — 순서 변경**: Click 또는 초점 상태에서 Enter/Space 시 오름차순/내림차순 정렬 상태가 토글된다.
