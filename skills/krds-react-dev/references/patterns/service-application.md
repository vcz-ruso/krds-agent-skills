# 신청

## 개요

신청은 사용자가 서비스 제공 기관에 요구 사항을 알리기 위해 서식을 작성하는 과업으로, 관련 법률에 명시된 종류의 민원 외에 사용자가 특정한 내용을 요청하는 모든 행동을 포함한다.

**유형**

| 유형 | 설명 | 예 |
| --- | --- | --- |
| 제출 | 정해진 서식에 따라 신청서를 작성하여 제출 | 복지 급여 신청, 전입신고, 귀국신고 |
| 조회 | 자격, 문서 효력, 처분 결과 등을 확인 | 문서 진위 확인, 세액 조회 |
| 발급 | 증명 서류, 자격 번호 등을 발급 | 주민등록 등·초본 발급, 개인통관번호 발급, 자동차 등록증 발급 |
| 예약 | 일정 기간 재화/서비스 이용을 신청 | 도서 예약, 좌석 예약, 관람 예약/예매 |

이용 상황별 플로: (1) 신청 대상 탐색 → (2) 서비스 정보 확인 → (2.5) 유의 사항/자격 확인 → (3) 신청서 작성 → (4) 확인·확정 → (5) 완료 → (6) 신청 결과 확인.

서비스 패턴의 사용성 가이드라인은 사용자 관점의 중요도·만족도에 따라 **[필수]-[권장]-[우수]** 3개 적용 수준으로 구분된다. 핵심 서비스는 최하위 수준인 [필수]를 반드시 준수해야 한다.

## 사용자 여정 단계

### 1. 신청 대상 탐색

**구조**: ① 필터링·정렬 컨트롤, ② 페이지네이션, ③ 항목(제목=상세 이동 링크, 꺾쇠/화살표, 미리보기/요약, 배지(예정됨/접수 중/마감됨), 메타데이터, 저장 컨트롤, 액션 버튼).

- **[권장]** 신청 서비스의 특성에 따른 적절한 서비스 목록 정렬 방식을 사용한다 — 상시 신청은 가나다순, 한시적/마감형은 신청 가능한 서비스 우선 배치.
- **[권장]** 목록을 적절한 방식으로 군집화하여 메타 데이터를 부여한다.
- **[필수]** 신청 상태 정보를 명확하게 인지할 수 있도록 표현한다(한시적/마감형은 배지로 반드시 표시).
- **[권장]** 미리보기/요약에 신청 가능 기한 정보를 제공한다.
- **[필수]** 제목에 공식적인 서비스 명칭을 사용한다(통용되는 별칭은 괄호 보조 설명 또는 검색 결과로만 노출).
- **[필수]** 제목에 말줄임표를 사용하지 않는다.
- **[권장]** 미리보기/요약 텍스트는 간결하게 작성한다.
- **[권장]** 상세 화면을 거치지 않고 신청 과정에 바로 접근할 수 있는 액션 버튼을 제공한다.
- **[권장]** 외부 서비스로 이동하거나 새 창을 실행하는 액션 버튼에 명확한 시각적 단서를 제공한다.

**플랫폼 고려 사항**: 검색어 입력창에 음성입력 버튼을 제공한다. 모바일 앱 필터 컨트롤은 모달/바텀시트로 표현할 수 있다. 상세 검색 컨트롤은 모바일 앱 화면 크기를 고려해 숨김 처리할 수 있다.

**접근성 가이드라인**: 공유/저장 컨트롤과 액션 버튼에 명확한 접근 가능한 이름을 제공한다 — 동일 레이블의 컨트롤이 목록에 여러 개 있을 때 `title` 또는 `aria-describedby`로 대상을 변별한다. 관련: KWCAG 2.2 적절한 링크 텍스트, WCAG 2.1 Headings and Labels(AA)/Label in Name(A)/Name, Role, Value(A).

관련 기본 패턴: 목록 탐색, 필터링·정렬.

### 2. 서비스 정보 확인

**구조**: ① 제목(신청 서비스명), ② 요약 정보, ③ 개요 정보, ④ 상세 정보, ⑤ 부가 정보, ⑥ 콘텐츠 변경 이력, ⑦ 콘텐츠 내 탐색(in-page navigation), ⑧ 액션 버튼.

- **[권장]** 본문 콘텐츠의 제목을 신청 서비스명으로 제공한다.
- **[필수]** 상세 정보 콘텐츠는 간결하며 이해하기 쉽게 작성한다(불가피한 전문 용어·외국어는 도움 컴포넌트로 설명).
- **[필수]** 상세 정보는 정확하고 최신화된 상태로 제공한다 — 특히 신청 기간, 상태, 지원 금액, 문의처는 오류 시 치명적 결과로 이어질 수 있다.
- **[필수]** 서비스를 신청할 수 있는 모든 채널(방문/대면, 전화, 우편, 온라인)과 제약 사항에 대한 정보를 제공한다.
- **[필수]** 온라인으로 신청할 수 없는 상황을 명확하게 인지 가능하도록 표현한다.
- **[필수]** 사용자가 신청 과업을 완료하는 데 필요한 모든 서식과 서류에 대해 안내하고 빠르게 접근할 수 있는 수단(다운로드, 외부 서비스 링크)을 제공한다.
- **[필수]** 신청 과정과 처리 절차에 대한 정보를 제공한다.
- **[권장]** 일반적으로 신청 과정에 소요되는 기간 정보를 절차별로 안내한다.
- **[권장]** 사용자에게 도움을 줄 수 있는 다양한 부가 정보(문의처, 관련 서비스 링크, 함께 이용한 서비스, FAQ)를 제공한다.
- **[권장]** 기본 정보는 한 화면에 확인 가능하도록 제공한다(탭·아코디언으로 분할하지 않음).
- **[필수]** 탭 레이아웃을 사용해야 한다면 기본 정보는 첫 번째 탭에서 확인 가능하도록 제공한다.
- **[권장]** 부가 정보는 사용자가 필요에 따라 상세 내용을 확인할 수 있게 제공하는 방안(일부만 표시 후 확장)을 고려한다.
- **[권장]** 모든 링크는 실행하였을 때, 링크 레이블에 명시된 적절한 화면으로 이동해야 한다.
- **[권장]** 목록 이동 버튼 또는 브라우저 뒤로가기 실행 시 사용자의 탐색 맥락(페이지 번호, 항목 위치, 필터링·정렬 옵션)이 유지되어야 한다.

관련 기본 패턴: 상세 정보 확인, 첨부파일.

### 3. 유의 사항/자격 확인

**구조**: ① 배지, ② 안내 정보(취소/수정 가능 여부, 전자서명/본인인증 절차 포함 여부, 제출할 증빙서류, 기타 안내사항), ③ 디스클로저, ④ 액션 버튼.

**유형**

| 구분 | 안내 섹션 | 단일 화면 |
| --- | --- | --- |
| 신청 취소/철회 | 해당 없거나 가능함 | 어렵거나 불가능함 |
| 제출된 서식 수정 | 해당 없거나 가능함 | 어렵거나 불가능함 |
| 신청 자격 제한 | 제한 없음 | 신청 조건에 따라 가능 여부 결정 |
| 작성 단계·속도 | 단계가 적고 서식이 간단함 | 단계가 많고 시간·노력이 많이 소요됨 |

- **[권장]** 유의 사항 및 자격 확인은 신청서 작성 과업의 가장 첫 단계로 제공한다 — 이미 많은 정보를 입력한 뒤 자격 미달을 확인시키면 사용자가 헛수고를 하게 된다.
- **[필수]** 신청서 작성 중간이나 최종 단계에서 작성을 중단해야 하는 상황에 대해 사용자에게 명확하게 안내한다.
- **[권장]** 중요도와 계층 구조에 따라 정보를 직관적으로 인지할 수 있도록(목록, 표 등으로) 표현한다.
- **[권장]** 신청서 작성 단계 중에 필요한 정보, 신청 완료 이후 필요한 정보는 포함하지 않는다.

관련 기본 패턴: 도움, 동의, 입력폼.

### 4. 신청서 작성

**구조**: ① 제목, ② 설명(선택), ③ 입력폼, ④ 단계 표시기, ⑤ 도움 패널, ⑥ 어노테이션 아이콘(도움 패널 실행 버튼).

- **[필수]** 한 단계 내에서의 신청 서식 섹션을 탭이나 아코디언으로 구분하지 않는다 — 사용자가 탭/아코디언의 존재를 인지하지 못해 입력 오류를 유발할 수 있다.
- **[권장]** 값의 변경이 이전에 작성한 항목 또는 이전 단계에 영향을 미치는 경우, 이전 입력 항목 또는 이전 단계에 포함시킨다.
- **[필수]** 값의 변경이 이전 항목/단계에 영향을 미치는 상황을 사용자에게 안내해야 한다(구조적으로 순서 설계가 어렵다면 인라인 메시지로 안내).
- **[권장]** 행정정보 공동이용 시스템을 활용하여 사용자의 구비서류 첨부를 최소화한다.
- **[권장]** 여러 단계로 구성되거나 작성에 시간이 걸리는 신청서 작성 과정에 임시 저장 기능을 제공한다.
- **[권장]** 입력 항목에 대한 레이블에 설명을 제공한다(전문 용어는 도움 컴포넌트로 보완).
- **[필수]** 신청서 작성에 대해 도움받을 수 있는 다양한 수단을 제공한다 — 문의처(전화/이메일/챗봇), 도움 컴포넌트(어노테이션·도움 패널·코치마크), FAQ, 작성 예시 콘텐츠 링크 중 1가지 이상.
- **[권장]** 도움말은 이용 맥락에 맞게(입력 항목 자체에) 제공한다.
- **[필수]** 도움말은 정확한 내용으로 제공한다.
- **[필수]** 초기화 버튼은 다른 버튼과 명확하게(시각적·공간적으로) 구분한다.

### 5. 확인·확정

**구조**: ① 제목, ② 설명(선택), ③ 확인 정보 목록, ④ 액션 컨트롤(제출 확정/중단·이전 단계 복귀).

**유형**: 모달(안내 정보량이 적어 스크롤 없이 표현 가능한 경우), 단일 화면(정보량이 많아 구조화가 필요한 경우).

- **[필수]** 신청 취소/철회, 제출된 신청 서식 수정이 불가능한 경우 확인·확정 단계를 반드시 포함해야 한다(단, 결과를 되돌릴 수 없어도 반복 신청 가능한 발급형은 생략 가능).
- **[권장]** 작성한 내용 중 핵심 정보(연락처, 취소/수정 불가 정보, 심사·결과에 영향을 미치는 정보 등)를 요약하여 제공한다.
- **[필수]** 취소/수정 불가한 사항에 대해 사용자에게 명확하게 안내해야 한다.
- **[필수]** 행동을 확정, 취소할 수 있는 버튼을 모두 제공한다.

### 6. 완료

**구조**: ① 제목, ② 확인 정보(핵심 입력 정보 요약), ③ 액션 컨트롤(신청 내역 화면 링크, 관련 서비스 링크, 다시 신청하기 버튼).

- **[필수]** 모든 신청 과업에는 완료 단계를 제공한다 — 피드백 없이 메인/신청 내역 화면으로 바로 이동하면 사용자가 당황할 수 있다.
- **[권장]** 작성한 내용 중 핵심 정보를 요약하여 제공한다(단, '확인/확정' 단계가 이미 있었다면 생략 가능).
- **[권장]** 신청 결과를 확인할 수 있는 화면으로 연결된 링크를 제공한다.
- **[우수]** 사용자가 빈번하게 동일한 신청 서비스를 연속적으로 이용하는 경우, 같은 작업을 다시 수행할 수 있는 버튼을 제공한다.
- **[권장]** 관련된 신청 서비스 정보를 확인하거나 신청할 수 있는 링크를 제공한다.

### 7. 신청 결과 확인

**구조**: ① 필터링·정렬 컨트롤, ② 페이지네이션, ③ 제목(상세/이력 화면 링크), ④ 메타데이터(신청일/취소일, 처리 절차/진행 상태), ⑤ 액션 버튼(인쇄/저장, 신청 취소).

- **[권장]** 신청 결과 확인 화면으로 이동하는 링크 레이블에 직관적인 명칭('신청 현황', '신청 내역')을 사용한다.
- **[필수]** 신청 내역(서식의 모든 항목과 입력값)을 제공한다 — 문서로 대체되는 경우 문서에 없는 정보는 별도 제공.
- **[필수]** 신청 이력을 제공한다.
- **[권장]** 신청 이력을 알기 쉽게(표·목록으로) 구조화한다.
- **[권장]** 정렬 기능(신청 일자, 중요도, 마감 기한 등)을 제공한다.
- **[필수]** 신청 처리 절차 및 현재 진행 상태에 대한 정보를 제공한다.
- **[권장]** 일괄 선택 기능을 제공한다.
- **[권장]** 신청 취소 버튼을 명확하게 표현한다.

**접근성 가이드라인**: 신청 내역 선택에 사용되는 체크박스에 적절한 레이블(예약명, 예약번호 등)을 제공한다 — 동일 레이블의 체크박스가 여러 개면 보조 기술 사용자가 대상을 구분할 수 없다. 관련: KWCAG 2.2 레이블 제공, WCAG 2.1 Labels or Instructions(A)/Headings and Labels(AA).

관련 기본 패턴: 목록 탐색, 필터링·정렬.
