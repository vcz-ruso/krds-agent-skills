# eval-a11y-review — 시나리오

## 대상 스킬

`skills/krds-a11y-review`

## 전제 조건

1. `krds-a11y-review` 스킬이 설치된 Claude Code 세션에서 실행한다(리포지터리 루트에서 실행하는 세션이면 스킬이 자동 인식된다).
2. 이 디렉터리의 `fixtures/bad-form.tsx`를 리뷰 대상으로 그대로 사용한다. 별도 프로젝트로 옮길 필요 없이 리포지터리 안의 실제 경로(`evals/eval-a11y-review/fixtures/bad-form.tsx`)를 프롬프트에서 그대로 지정한다.
3. 이 fixture는 diff 없이 파일 경로만 주어지는 상황이므로, `krds-a11y-review` SKILL.md §1의 분기 규칙에 따라 스킬은 **전체 파일 리뷰**로 폴백해야 한다(별도로 "전체 파일 리뷰해줘"라고 요청하지 않는다 — 이 분기 판단 자체도 평가 대상이다).
4. 세션은 리뷰만 요청받는다. 코드 수정을 함께 요청하지 않는다(이 스킬은 리뷰 전용이므로 코드를 고치면 안 된다는 것 자체가 rubric 항목이다).

## 사용자 프롬프트 (원문)

```
evals/eval-a11y-review/fixtures/bad-form.tsx 파일 접근성 리뷰해줘.
```

## 관찰 포인트

- `scripts/check-static.mjs`를 실제로 실행하는가, 아니면 실행하지 않고 코드를 눈으로만 훑어 리포트를 지어내는가.
- `check-static.mjs`가 실제로 검출하는 5개 규칙(하드코딩 색상, 터치 타깃 휴리스틱, img alt 부재, 접근 가능한 이름 부재, `<div onClick>`)과, 이 fixture에 있는 **5종 위반 중 하나(폼 필드 label 부재)가 이 스크립트의 검사 범위 밖**이라는 점을 스킬이 스스로 파악하고 §3 모델 판단으로 보완하는지가 이 평가의 핵심이다. 스크립트 출력만 그대로 옮기고 label 누락을 놓치는 세션은 실패로 채점한다.
- "코드상 확정"과 "수동 검증 필요"를 뒤섞지 않고 절을 나눠 제시하는지.
