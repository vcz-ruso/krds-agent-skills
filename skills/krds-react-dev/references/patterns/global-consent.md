# 동의

## 개요

동의는 웹사이트의 이용 조건 및 절차 등을 명시한 내용을 읽고 동의 여부나 안내 사항의 확인 여부를 확인하는 데 사용되는 패턴이다. 대개 동의가 필요한 약관은 일반적으로 잘 사용되지 않는 용어로 작성되며 양이 매우 방대하므로, 사용자의 이해를 도울 수 있도록 요소들을 알기 쉽게 구조화해야 한다.

## 구조

1. **일괄 동의 옵션** — a. 체크박스(동의 목록 전체 항목의 동의 옵션 선택 상태를 토글), b. 설명(전체 동의 항목 정보와 선택 동의 항목에 대한 설명)
2. **목록** — a. 컨테이너(항목 구분자), b. 제목(각 항목의 콘텐츠 제목), c. 본문(약관 등 상세 설명), d. 동의 옵션(라디오 버튼 또는 체크박스)

## 사용성 가이드라인

- **동의하지 않음 옵션을 제공한다.** 대안을 선택할 수 있는 기회를 제공받으면 사용자는 약관에 동의하는 행동이 더욱 의미 있다고 느끼게 된다.
- **동의함/동의하지 않음 옵션은 구분하기 쉽게 표현한다.** 옵션이 다른 요소들과 잘 구분되지 않으면 사용자가 선택 과정 없이 다음 단계로 넘어가려다 오류가 발생할 수 있다.
- **[필수]** 필수 항목과 선택 항목 정보를 제공하고 명확하게 구분될 수 있도록 표현한다. 사용자가 동의하지 않아도 서비스 이용에 문제가 없는 선택적 동의 항목과 필수 동의 항목은 명확히 구분되어야 한다 — 동의 항목 제목에 '필수'/'선택' 텍스트를 표시하고, 필수 항목은 목록 상단에 그루핑하여 배치한다.

## 접근성 가이드라인

- **키보드를 이용하여 약관 내용을 확인할 수 있도록 제공한다.** 약관 내용 영역의 스크롤은 키보드로 조작 가능해야 하며, 키보드 사용자가 스크롤 하단에 숨겨진 내용을 확인할 수 있어야 한다. 관련: KWCAG 2.2 키보드 사용 보장, WCAG 2.1 Keyboard(A)/No Keyboard Trap(A).
- **약관 내용을 적절하게 구조화하여 제공한다.** 제목, 문단 등으로 구조화하면 보조 기기 사용자가 콘텐츠를 탐색·이해하기 쉬워진다. 관련: KWCAG 2.2 제목 제공, WCAG 2.1 Info and Relationships(A).
- **동의함/동의하지 않음 옵션에 설명을 제공한다.** 라디오 버튼 레이블은 양식 오른쪽에 배치한다. 동의 항목이 여러 개일 때는 `aria-describedby` 속성으로 각 라디오 버튼과 해당 동의 항목의 제목을 연결해, 스크린 리더 사용자가 어떤 항목에 대한 동의 옵션인지 명확히 확인할 수 있도록 한다. 관련: KWCAG 2.2 레이블 제공, WCAG 2.1 Info and Relationships(A)/Labels or Instructions(A).

## 상호작용 가이드라인

**목록 탐색**

| 키 | 동작 |
| --- | --- |
| Tab | 목록 내 다음 요소로 키보드 초점 이동, 포커스링 표시 |
| Shift + Tab | 목록 내 이전 요소로 키보드 초점 이동, 포커스링 표시 |

**동의 옵션 선택 — 일괄 선택**: 개별 선택 항목 중 하나라도 '동의 안 함'이 선택되어 있다면 일괄 선택 체크박스는 선택 해제 상태가 유지되어야 한다.

| 조작 | 동작 |
| --- | --- |
| Click | 일괄 선택 체크박스 선택 시 모든 동의 옵션이 '동의함'으로, 해제 시 모두 '동의 안 함'으로 전환. 초점은 체크박스에 유지 |
| Space | Keyup 이벤트 발생 시 Click과 동일하게 토글, 초점은 체크박스에 유지 |

**동의 옵션 선택 — 개별 선택**: 라디오 버튼과 체크박스 컴포넌트의 가이드라인을 따른다.
