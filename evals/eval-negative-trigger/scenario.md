# eval-negative-trigger — 시나리오

## 이 평가의 성격 (음성 평가)

이 저장소의 다른 4개 평가는 스킬이 **적용되어야 할 때 올바르게 작동하는지**(양성 평가)를 본다. 이 평가는 반대로,
KRDS와 무관한 요청에서 스킬이 **적용되지 않아야 하는지**(음성 평가, negative trigger test)를 본다.

세 스킬의 `description`은 각각 "Korean government service UI", "Korean government service UI code
accessibility", "Korean government services" 같은 트리거 경계를 명시하고 있다(각 SKILL.md 프런트매터
`description` 참고). 이 요청은 정부 서비스도, KRDS도 아닌 **사내(민간 기업) 어드민 대시보드**이며 이미
자체 브랜드 컬러가 정해져 있다. 이 스킬들의 description 트리거 경계가 실제로 이 요청에서 스킬을 발동시키지
않는지 — 발동시키더라도 세션이 KRDS 규칙(토큰 강제, 하드코딩 색상 금지, krds-react 컴포넌트 강제 등)을
사용자 요청 위에 부적절하게 덮어씌우지 않는지 — 를 확인한다. 즉 이 평가에서 "필수" 항목은 전부 **"~하지
않아야 한다"** 형태이며, 스킬이 아무것도 하지 않는 것(또는 미미하게만 관여하는 것)이 통과다.

## 대상 스킬

`skills/krds-react-dev`, `skills/krds-a11y-review`, `skills/krds-design` 전체(어느 스킬도 과잉 발동하지
않아야 함을 확인하는 평가이므로 특정 스킬 하나가 아니라 셋 다 대상이다).

## 전제 조건

1. 세 스킬이 모두 설치된 Claude Code 세션에서 실행한다(설치되어 있어야 "발동하지 않음"을 검증하는 의미가
   있다 — 애초에 설치 안 된 세션에서는 이 평가가 무의미하다).
2. 대상 프로젝트는 KRDS와 무관한 일반 사내 React/Next.js 프로젝트라고 가정한다.
3. 정부·공공기관·KRDS라는 단어는 프롬프트에 전혀 등장하지 않는다.

## 사용자 프롬프트 (원문)

```
사내 어드민 대시보드 만들어줘, 우리 회사 브랜드 컬러는 #FF6B35야
```

## 관찰 포인트

- 세션이 `krds-react` 컴포넌트 import를 시도하거나, 응답에 "KRDS", "krds-react", "토큰" 같은 용어를
  근거 없이 끌어오는가.
- `#FF6B35`를 그대로 쓰지 못하게 막거나 "하드코딩 금지, `var(--krds-*)`를 쓰라"고 요구하는가.
- krds-a11y-review 스킬 특유의 KWCAG/WCAG 인용 리포트 형식을 이 요청에 강제하는가(접근성 자체에 대한
  일반적인 조언은 음성 평가 실패 사유가 아니다 — KRDS 특유의 인용 형식·리포트 템플릿을 강제하는 것이
  문제다).
