# 사용자 피드백

## 개요

사용자 피드백은 사용자로부터 특정 화면이나 기능 이용 경험에 대한 평가 의견, 불편 사항, 제안 사항을 수집하는 데 사용되는 패턴이다. 서비스 이용 맥락에서 직접적으로 사용자의 의견을 수집할 수 있는 수단이므로 서비스 운영에 매우 중요한 요소이나, 사용자가 의견을 남기는 것이 의무 사항이 아니므로 사용자의 과업을 방해하지 않으면서 의견을 남기도록 유도하는 것이 중요하다.

## 구조

1. **제목** — 의견을 구할 대상을 설명하는 질문 형식의 간결한 텍스트
2. **설명(선택)** — 제목에 대한 부가 설명
3. **평가** — a. 감정 표현(만족/불만족 형식), b. 별점(1~5점 정량 평가)
4. **맞춤 영역(선택)** — a. 제목, b. 질문(1~3개, 라디오 버튼/체크박스/텍스트 입력 필드), c. 액션 버튼(응답 안 함/제출)
5. **완료 메시지** — 피드백 제출 완료를 알리는 메시지

## 용례

**사용하기 적합한 경우**: 화면별 사용자의 이용 의견을 상시적으로 확인하고자 하는 경우, 새로운 기능이나 정보에 대한 의견을 확인하고자 하는 경우.

**사용하기 적합하지 않은 경우**: 서비스 전체에 대한 종합적인 사용자 의견을 수렴하고자 하는 경우 — 다수의 질문과 단계가 필요한 입력폼이 필요하므로 별도 화면을 구성하는 것이 적절하다.

## 사용성 가이드라인

- **사용자 피드백은 화면 하단 또는 본문의 사이드 영역에 배치한다.** 사용자가 방해 없이 본문 정보·기능을 이용한 후 피드백을 남길 수 있도록 화면 하단에 배치한다. 본문 너비가 충분하고 화면 복잡도가 높지 않다면 사이드 영역에 배치할 수 있다.
- **사용자 피드백을 시의적으로 사용하는 경우 사용자의 작업이 완료된 후에 유도 메시지를 제공한다.** 페이지 로딩 직후 강조되어 표현되면 사용자에게 방해가 된다.
- **사용자 피드백은 폐쇄형 질문으로 시작한다.** 선택 가능한 값이 정해진 폐쇄형 질문을 기본 평가 질문으로 제공해야 한다 — 개방형 질문이 시작 질문이면 사용자가 많은 노력이 필요하다고 판단해 피드백을 포기할 수 있다.
- **평가의 선택지를 최소화한다.** 선택지가 늘어날수록 응답 시간과 실수가 증가한다. 감정 평가는 가능한 2가지 선택지로, 별점은 5개를 초과하지 않도록 한다.
- **맞춤 영역의 질문을 간결하게 구성한다.** 추가 질문은 최대 3개만 사용한다. 심도 깊은 평가가 필요하면 별도 화면·채널을 활용해야 한다.
- **맞춤 영역의 질문에 대한 응답 방식을 유연하게 구성한다.** 개방형 질문은 폐쇄형에서 미처 표현하지 못한 의견을 수집하는 데 효과적이지만 사용자에게 부담을 줄 수 있으므로 가장 마지막 질문으로 사용하는 것이 좋다.

## 플랫폼에 대한 고려 사항

**화면 너비가 충분하지 않은 경우, 어사이드에 배치된 사용자 피드백은 화면 하단에 배치한다.** 사용자 피드백을 플로팅 버튼으로 축약하지 않고 화면 하단에 배치해 방해 없이 이용 후 피드백을 남길 수 있도록 한다.

## 접근성 가이드라인

- **각 입력 필드와 입력폼에 이름을 제공한다.** 스크린 리더에서 각 입력 요소의 용도를 이해할 수 있도록 접근 가능한 이름을 제공해야 한다. 관련: KWCAG 2.2 레이블 제공, WCAG 2.1 Info and Relationships(A)/Name, Role, Value(A).
- **맞춤 영역, 완료 메시지에 live-region을 적용한다.** 맞춤 영역의 출현이나 완료 메시지로의 전환을 스크린 리더 사용자가 인지하지 못할 수 있으므로 `aria-live="polite"`를 사용자 피드백 구획에 제공한다. 관련: WCAG 2.1 Name, Role, Value(A)/Status Messages(AA).

## 상호작용 가이드라인

**맞춤 영역의 요소 탐색**: Tab / Shift+Tab — 맞춤 영역 내부의 입력 서식 요소, 액션 버튼에 키보드 초점이 순차적으로 접근한다.

**최종 응답 제출**

| 조작 | 동작 |
| --- | --- |
| Click | 취소 또는 평가 완료 버튼 클릭 시 평가 입력폼이 제출 완료되며 완료 메시지가 제공된다 |
| Enter, Space | 버튼이 초점을 가진 상태에서 Keyup 이벤트 발생 시 동일하게 제출·완료 메시지 표시 |

**평가 선택**

| 조작 | 동작 |
| --- | --- |
| Click | 감정 표현/별점 버튼 클릭 시, 맞춤 영역이 있으면 컨테이너 높이가 확장되며 맞춤 영역이 하단에 표시된다. 맞춤 영역이 없으면 평가가 즉시 제출되고 헤딩·설명이 완료 메시지로 대체된다 |
| Enter, Space | 버튼이 초점을 가진 상태에서 Keyup 이벤트 발생 시 Click과 동일하게 동작하며, 초점은 선택한 평가 버튼에 유지된다 |
